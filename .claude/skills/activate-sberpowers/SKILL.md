# activate-sberpowers — точка входа набора

<КРИТИЧНО>
Этот скилл читается В НАЧАЛЕ СЕССИИ, до любого ответа — включая уточняющие вопросы.

Перед началом задачи ОПРЕДЕЛИ релевантный скилл и ПОЛНОСТЬЮ прочитай его тело:
`skills/<имя>/SKILL.md`. Дальше следуй телу скилла шаг за шагом.

НЕ действуй по памяти. НЕ пересказывай description как инструкцию — description
лишь помогает выбрать скилл; исполняется ТОЛЬКО прочитанное тело SKILL.md.
Если хоть 1% вероятности, что скилл применим — открой и прочитай его.
</КРИТИЧНО>

## Индекс скиллов

`manual` — предложи пользователю и жди явного вызова. `auto` — применяй сам, как только сработал триггер.

| Скилл | Когда | Режим |
|---|---|---|
| discover | Только сырая идея/тикет: собрать факты о задаче и коде до решений | manual |
| grill | Сократический допрос требований до общего понимания | manual |
| specify | Оформить согласованное понимание в delta/baseline-спеку с REQ-ID | manual |
| plan | Спека → вертикальные срезы, волны, задачи-промпты | manual |
| execute | Исполнить план субагентами: задача → атомарный коммит | manual |
| review | Проверить результат: соответствие спеке (REQ-ID) + качество кода | manual |
| learn | Закрыть цикл: worklog, уроки, подводные камни, при значимости — ADR | manual |
| systematic-debugging | Любой баг, падение теста, необъяснённая ошибка, регрессия | auto |
| refactoring-safely | Структурная правка без смены поведения под зелёными тестами | auto |
| verification-before-completion | Перед любым «готово/исправлено/проходит», перед commit/PR | auto |
| git-discipline | На коммитах, старте и завершении ветки | auto |
| skill-creator | Только при создании или правке самих скиллов набора | manual |

## Главный поток

```
discover → grill → specify → plan → execute → review → learn
 факты     допрос   спека     срезы   субагенты  2 оси    уроки/ADR
```

Поверх потока авто-дисциплины срабатывают сами:
- **verification-before-completion** — перед любым заявлением об успехе;
- **systematic-debugging** — при баге или падении теста;
- **git-discipline** — на коммитах и завершении ветки;
- **refactoring-safely** — при структурных правках под зелёными тестами.

## On-ramps (в обход полной цепочки)

- Пришёл баг / упал тест → сразу **systematic-debugging**.
- «Сделай ревью» / проверь против спеки → сразу **review**.
- Мелкая однозначная фича без открытых вопросов → сразу **specify** (discover/grill пропускаются).
- Создать или поправить скилл → **skill-creator**.

## Неотменяемые дисциплины

- Никакого «готово/проходит» без свежего прогона команды проверки и прочтения её вывода.
- Один таск → один атомарный коммит со scoped-сообщением.
- Спека — это **delta** (что меняется), а не документ для чтения; требования проверяемы и с REQ-ID.
- Тесты пишутся до или вместе с кодом, не после.

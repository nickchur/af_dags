# Одноразовый прототип — выбор ветки и правила

Когда читать: из раздела «Опционально: одноразовый прототип» скилла discover,
когда открытый вопрос — про ощущение логики или про внешний вид, а не про факт
из кода. Источник паттерна — приём «prototype» инженерных наборов; здесь он
адаптирован под фазу discover: прототип отвечает на design-вопрос до specify,
не заменяет реализацию.

## Прототип — это одноразовый код, отвечающий на один вопрос

Вопрос решает форму. Не строй прототип, если вопрос уже закрыт цитатой из кода
или доки, — это уже факт, а не design-вопрос.

## Выбери ветку

- **«Эта стейт-модель / эта логика ощущается верной?»** — собери крошечное
  интерактивное консольное приложение, которое прогоняет модель через
  состояния, трудно проверяемые на бумаге: гонки, повторные события,
  граничные переходы.
- **«Как это должно выглядеть?»** — сгенерируй несколько радикально разных
  вариантов интерфейса на одном экране/роуте, переключаемых параметром — без
  привязки к финальной вёрстке.

Вопрос неоднозначен и уточнить не у кого — выбери ветку по соседнему коду
(бэкенд-модуль → логика; страница/компонент → интерфейс) и явно зафиксируй
это допущение в начале прототипа.

## Правила, общие для обеих веток

1. **Одноразовость видна с первой секунды.** Имя файла/каталога само
   говорит «это прототип, не продакшен»; располагай рядом с местом, которое
   он прототипирует, — контекст должен быть очевиден.
2. **Одна команда запуска.** Тем инструментом, который уже есть в проекте.
   Пользователь стартует прототип не думая, каким рантаймом и как.
3. **Без персистентности по умолчанию.** Состояние — в памяти. Если вопрос
   прямо касается хранилища — используй одноразовую БД/файл с именем вида
   «PROTOTYPE — можно стереть».
4. **Без полировки.** Ни тестов, ни обработки ошибок сверх необходимого для
   запуска, ни абстракций. Цель — быстро получить ответ, не сдать код в ревью.
5. **Состояние видно на каждом шаге.** После каждого действия (логика) или
   при каждом переключении варианта (интерфейс) — печатай/рендери всё
   существенное состояние целиком.
6. **Зафиксируй результат, не код.** Прототип целиком уходит в throwaway-
   ветку — вне основной ветки; в конспект discover и дальше в спеку попадает
   только вывод: какой вариант выбран и почему, при необходимости — решающий
   фрагмент (сигнатура, стейт-машина), помеченный происхождением «из
   прототипа, discover YYYY-MM-DD». Основная ветка не видит прототипный код.

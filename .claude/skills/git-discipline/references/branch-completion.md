# Завершение ветки — команды по вариантам меню

Читай этот файл после того, как человек выбрал пункт меню из SKILL.md. Ниже — точные команды на каждый вариант, порядок операций и провенанс-проверка перед удалением воркспейса.

## Определение base-ветки

Перед меню (или сразу после выбора «merge») определи, от чего ответвилась ветка:

```bash
git merge-base HEAD main 2>/dev/null || git merge-base HEAD master 2>/dev/null
```

Не нашлось ни одной — спроси человека прямо: «Ветка ответвилась от `<X>` — верно?».

## Вариант 1: слить локально

Порядок обязателен: merge → тесты на результате → только потом cleanup и удаление ветки. Обратный порядок (удалить воркспейс до подтверждения успешного merge) необратим при ошибке.

```bash
# Перейти в корень основного репозитория (не работать из воркспейса, который вот-вот удалим)
MAIN_ROOT=$(git -C "$(git rev-parse --git-common-dir)/.." rev-parse --show-toplevel)
cd "$MAIN_ROOT"

git checkout <base-branch>
git pull
git merge <feature-branch>

# Полный прогон тестов на слитом результате — не на состоянии до merge
<команда тестов проекта>
```

Тесты красные на результате слияния → не удалять ничего, разбираться с конфликтом смысла, а не откатывать merge вслепую.

Тесты зелёные → provenance-cleanup (см. ниже), затем:

```bash
git branch -d <feature-branch>
```

## Вариант 2: создать Pull Request

```bash
git push -u origin <feature-branch>
```

Воркспейс **не удаляется** — он нужен человеку для итераций по фидбеку ревью. Cleanup не запускается ни при каких условиях для этого варианта.

## Вариант 3: оставить как есть

Никаких команд. Доложить одной строкой: ветка `<name>` сохранена, воркспейс на месте по пути `<path>`. Cleanup не запускается.

## Вариант 4: выбросить работу

Обязательно типизированное подтверждение до любого удаления — показать, что именно теряется:

```
Будет удалено безвозвратно:
- Ветка <name>
- Коммиты: <commit-list>
- Воркспейс: <path>

Введите «выбросить» для подтверждения.
```

Ждать точное совпадение текста подтверждения. Без него — не выполнять ничего дальше.

Подтверждено → provenance-cleanup (см. ниже), затем:

```bash
MAIN_ROOT=$(git -C "$(git rev-parse --git-common-dir)/.." rev-parse --show-toplevel)
cd "$MAIN_ROOT"
git branch -D <feature-branch>
```

## Detached HEAD — варианты без merge

Вариант «запушить как новую ветку и создать PR»:

```bash
git checkout -b <new-branch-name>
git push -u origin <new-branch-name>
```

Дальше — как вариант 2: воркспейс не трогать. Варианты «оставить как есть» и «выбросить» — как выше; merge недоступен, потому что detached HEAD не был именованной веткой, к которой применимо «слить».

## Provenance-cleanup (общая процедура для вариантов 1 и 4)

```bash
GIT_DIR=$(cd "$(git rev-parse --git-dir)" 2>/dev/null && pwd -P)
GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" 2>/dev/null && pwd -P)
WORKTREE_PATH=$(git rev-parse --show-toplevel)
```

- `GIT_DIR == GIT_COMMON` → обычный репозиторий, воркспейса для удаления нет. Готово.
- `WORKTREE_PATH` лежит под `.worktrees/` или `worktrees/` в корне репозитория → этот процесс его создал через фолбэк — владеем очисткой:
  ```bash
  MAIN_ROOT=$(git -C "$(git rev-parse --git-common-dir)/.." rev-parse --show-toplevel)
  cd "$MAIN_ROOT"
  git worktree remove "$WORKTREE_PATH"
  git worktree prune
  ```
  Запускать `git worktree remove` изнутри самого воркспейса — тихая ошибка; сначала обязательно `cd` в корень основного репозитория.
- Иначе (воркспейс создан нативным инструментом харнесса или вручную человеком) → не удалять. Если у харнесса есть штатный инструмент выхода/очистки — использовать его; иначе оставить воркспейс как есть.

## Частые ошибки

- Удалить ветку до удаления worktree — `git branch -d` откажет, пока worktree ссылается на ветку. Порядок: сначала worktree, потом ветка.
- Удалить воркспейс для варианта 2 — человеку нужен воркспейс живым для итераций по PR.
- Запустить `git worktree remove` находясь внутри удаляемого каталога — команда не сработает предсказуемо; всегда переходить в корень основного репозитория первым шагом.
- Чистить воркспейс, не лежащий под `.worktrees/`/`worktrees/`, — нарушение provenance-gate, даже если «он всё равно больше не нужен».

# sbp-writing

Скилл касается русского текста, который читают люди: артефактов OpenSpec, сообщений коммитов, описаний PR и документации. Промпт-файлы (скиллы, команды, инструкции агентов) подчиняются тем же правилам и разделу «Промпт-файлы» ниже.

При написании хватает правил из этого файла. `checklist.md` открывай при вычитке готового текста.

## Как писать

1. Первое предложение раздела сообщает факт или действие и не пересказывает заголовок.
2. Действие выражает глагол: «ревьюер проверяет шапку», «скопируй шаблон».
3. Исполнитель назван, если от него зависит смысл: «автор PR обновляет `tasks.md`». Системный пассив в справке допустим: «файл создаётся при первом запуске».
4. Одна сущность называется одним термином по всему тексту.
5. Свойство подкрепляется числом или фактом из источника: «повторяет запрос 3 раза с паузой 2 с». Данных нет — спроси автора.
6. Уверенность соответствует источнику. Сомнение выражается условием: «ускоряет сборку при тёплом кэше».
7. Текст заканчивается последним фактом или следующим шагом.
8. В перечне столько элементов, сколько их есть.
9. Связь между фразами держит их порядок. Связку ставь, когда без неё теряется логика.
10. Пунктуация по норме. Тире там, где его требует правило, и не больше двух на абзац. Кавычки «ёлочки», внутри них „лапки“. Числа по-русски: 1000, 10 000, 8,5.
11. Разметка следует содержанию. Нумерованный список для шагов, маркированный для однородных элементов, таблица для сравнения по нескольким признакам, абзац для причины и следствия. Жирный шрифт только для того, что ищут глазами, раз-два на экран.
12. По-английски пишутся идентификаторы, команды, пути и структурные токены OpenSpec. Устоявшиеся заимствования среды (коммит, ревью, промпт, PR) пишутся в одной форме на весь проект.

## Промпт-файлы

- Обычный императив без капса и восклицательных знаков: «Запусти `openspec validate --strict` перед коммитом».
- Сначала целевое поведение. Запрет ставится рядом с ним как жёсткая граница.
- Правило живёт в одном файле, в остальных стоит указатель на него.
- Причина пишется, если она меняет поведение исполнителя: неочевидное ограничение, прошлый сбой.
- Границы измеримы: порог, закрытый список или команда проверки.
- Description скилла говорит, что скилл делает и когда его вызывать. Главный триггер стоит первым.
- Промпт оформлен так, как должен выглядеть ответ.

## Факт-замок

При правке меняется форма, смысл остаётся прежним.

- Числа, версии, флаги, пути, имена и сроки берутся только из источника. Не хватает конкретики — задай вопрос автору и оставь исходную формулировку.
- Условия, оговорки с конкретным условием, порядок шагов и ссылки сохраняются.
- Правка убирает лишнее и выпрямляет фразы. Опыт, мнение, драматизм и ритм, которых не было в источнике, правка не добавляет.
- Найденный признак из чек-листа — повод перечитать фразу. Правь, если фраза становится точнее или короче без потери смысла.
- Признаки раздела A чек-листа и ложную антитезу (пункт 33) исправляй с первого случая. Остальные исправляй при скоплении: два-три в одном абзаце или один и тот же приём по всему тексту.

## Что не трогать

- Код, команды, пути, идентификаторы, YAML-ключи, цитаты, литералы.
- Структурные токены (список — в блоке SberPowers в `GIGACODE.md`), заголовки шаблонов схемы `sber-sdd` и тройки `**Вопрос:**` / `**Выбор:**` / `**Почему:**` в decisions.md: это формат, его читают OpenSpec и ревьюер.
- «X — Y» в определении термина и другое тире, которого требует норма.
- Повтор одного термина.
- Три элемента, если их правда три.
- Списки шагов, таблицы сравнения, одинаковый шаблон записей в справочнике и ранбуке.
- Оговорку с конкретным условием.
- Один блок «Внимание» о реальной угрозе потери данных.
- Устоявшиеся заимствования среды.
- Гладкий грамотный текст без признаков из чек-листа.
- Файлы, где плохие примеры приведены намеренно, например `checklist.md`.

## Порядок вычитки

1. Открой `checklist.md`.
2. Запусти механическую проверку из конца чек-листа по нужным файлам. Каждую находку посмотри глазами: совпадение внутри кода дефектом не считается.
3. Пройди текст по разделам чек-листа: A (следы переписки и генерации), B (канцелярит), C (лексика и кальки), D (риторические фигуры), E (пунктуация и типографика), F (разметка). Для промпт-файлов добавь раздел H.
4. Сверь факты по разделу G. Сравни исправленный текст с исходным: новых чисел, путей, флагов и имён в нём нет.
5. Если вычитку попросили, перечисли правки: было, стало, пункт чек-листа. Места, где не хватает данных, вынеси вопросами к автору.

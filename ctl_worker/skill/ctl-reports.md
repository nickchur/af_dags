# Отчёты CTL

*2026-09-26 21:51 MSK · v1.5 · Nick Churkin · [NSChurkin@sber.ru](mailto:NSChurkin@sber.ru)*

Навык для агента GigaCode с MCP-сервером Airflow альфы. Отчёты — обычные потоки CTL:
их SQL (`pr_mail_*`, `pr_check_*` в Greenplum) собирает HTML, тракт кладёт его в CTL
статистикой 12, CTL рассылает письмо. Ты читаешь тот же HTML таблицами.

Источник правды — SQL в папке `GP/srv_wf/functions/` репозитория `af_dags` и `GP/readme.md`.
Разбор отдельного потока из строки отчёта — навык `ctl-worker`, раздел 2а.

## 1. Как показать отчёт

1. `ctl_report()` — список отчётов: имя потока, `wf_exe`, расписание. Название из вопроса
   сопоставь с потоком (таблица раздела 2). Не нашёл — покажи список и спроси.
2. `ctl_report("<поток>")` — последняя законченная загрузка: `at`, `outcome`, `res`, `msg` и
   `tables` (заголовок раздела, колонки, строки).
3. Ответ: когда построен отчёт; по каждому разделу — сколько строк и что в нём важно
   (ошибки, «никогда», долгие, старые); сами строки — таблицей, если их до 15, иначе
   первые 10 и «ещё N». Цвета в `tables` не приходят: смысл выводи по значениям (раздел 3).
4. `source`: `log_bucket` — полная копия отчёта из бакета логов (всё, что построил SQL);
   `ctl` — собран из фрагментов CTL, большие разделы там могут отсутствовать. В разделе до
   50 строк, `rows_total` — сколько всего; назови его, если строк больше.
5. `note` вместо таблиц — HTML в загрузке нет: поток не отдаёт `html`, отчёт длиннее
   предела отправки или загрузка упала раньше (`outcome: error`, смотри `msg`).
6. Отчёт старый (`at` давнее расписания) — скажи это первым: данные на момент `at`.

## 2. Какие отчёты бывают

| Поток (`pc1080.…`) | Функция | Разделы | Про что |
|---|---|---|---|
| `mail_ctl_status` | `pr_mail_ctl_status` | `CTL Today`, `CTL All Active`, `CTL All WF`, `CTL All Today`, `CTL Not scheduled`, `Ztest Errors` | сводка загрузок по кодам `res` за день, активные, не на расписании |
| `mail_ctl_report` | `pr_mail_ctl_report` | `CTL Today` (+ `Errors`, `No data`, `Long`, `Done`, `Ok`, `Fcts`), `CTL Old and Working`, `CTL SDPUE Errors`, `CTL Not scheduled`, `GP Working`, `Lock` | подробно по загрузкам дня, что сейчас работает в Greenplum и кто кого блокирует |
| `mail_ctl_work_load_report` | `pr_mail_ctl_work_load_report` | `HR_Data Lake Speed / Skew / Ratio / Uncompress`, `CTL Yesterday Summary / Work Load / SDPUE / Errors / Long`, `CTL and GP Yesterday Errors`, `Yesterday Errors`, `CTL Not scheduled` | нагрузка и перекосы за вчера |
| `mail_ztest_report` | `pr_mail_ztest_report` | `Ztest Summary`, `Actual_date repeat`, `Row_count repeat`, `Ztest Details` | проверки качества (Z-тест) |
| `mail_sdpue_report` | `pr_mail_sdpue_report` | `SDPUE Last`, `SDPUE logged Last`, `SDPUE Errors`, `SDPUE logged Errors` | потоки внешних исполнителей (категория UE) |
| `mail_informatica_report` | `pr_mail_informatica_report` | `Informatica Last`, `Informatica Log` | загрузки Informatica |
| `mail_ctl_alerts` | `pr_mail_ctl_alerts` | `CTL Alerts` | SLA-алерты потоков (раздел 4) |
| `check_*` | `pr_check_ctl` → `pr_check_etl`, `pr_check_bd4ds` | одна таблица на объект или группу | свежесть и полнота данных объекта, бизнес-дата |

Точные имена потоков бери из `ctl_report()`: таблица — ориентир, на контуре их может быть
больше или часть на паузе. **Раздела без строк в отчёте нет вовсе**: нет `Lock` — блокировок
нет, нет `CTL Today Errors` — ошибок сегодня не было. Отсутствие раздела — это ответ, а не сбой.

## 2а. Отчёты подробно

Общее для всех `pc1080.mail_*`:

- **Заголовок `Last <время>`** — время последней записи журнала CTL (`tb_log_ctl`): отчёт
  строится по нему. В ответе `ctl_report` шапка — первая запись `tables` с `header: true`
  («CTL Today Report · Last 2026-09-26 21:18»). Цвет считается **в момент построения
  отчёта**, не сейчас: сравни `Last` с `at` отчёта. Разница до 2 мин — зелёный, 2–10 мин — тёмно-красный, больше
  10 мин — красный: к моменту отчёта журнал CTL не пополнялся, данные неполные — говорить об
  этом первым. С текущим временем `Last` не сравнивай: отчёт мог быть построен давно.
- **Последняя строка без `n`** в сводных разделах — итог по всем строкам.
- **`wf_sched`** — условие запуска: `and: p1033 [2] {926221020 ()}` = стратегия AND, профиль
  `p1033`, статистика 2, сущность 926221020; `or:` — хватит любого события.
- **`status_time`** — сколько загрузка в текущем статусе: от 3 ч бледно-жёлтый, 6 ч
  жёлтый, 12 ч золотой, сутки розовый, двое суток красный.
- **`auto`** — кто создал загрузку: `true` — CTL сам (по расписанию или событию), `false` —
  вручную или из Airflow (`NEW-AF`, ран вне расписания CTL).
- **`duration`** — длительность шага: от 30 мин бледно-жёлтый, 1 ч жёлтый, 1.5 ч розовый,
  2 ч лосось, 2.5 ч красный.

### `pc1080.mail_ctl_report` — «CTL Today Report», главный дежурный отчёт

| Раздел | Что в нём | На что смотреть |
|---|---|---|
| `CTL Today` | по категориям дерева `p1080`: `active` — потоков с активной загрузкой, `completed` — закончили сегодня, `cnt_ok` / `cnt_no` / `cnt_err` — по последнему итогу, `waited` — ещё не закончили, `delayed` — висят дольше своего `wf_interval` (по умолчанию сутки), `expired` — дольше двух | `cnt_err`, `expired`, `delayed` по категориям; итоговая строка |
| `CTL Old and Working` | активные загрузки, давно не менявшие статус: `status_dttm`, `status_time`, `status_info`, `wf_sched` | `status_time` в сутках. `EVENT-WAIT` неделями — событие не приходит (разбор — `ctl-worker` 2а). `RUNNING` сутками — загрузку не закрыли: у потока Airflow упал или не дошёл `run_end`, монитор перезапустит её через `run_stale` (6 ч) — если висит дольше, монитор её не видит (пауза дага, дага нет); у потока UE — `reStarted` через `ue_run_max` (сутки). Разбор — `ctl-worker`, «что с потоком» |
| `CTL SDPUE Errors` | ошибки потоков внешних исполнителей (категория UE) | чей поток, текст ошибки |
| `GP Working` | что прямо сейчас выполняется в Greenplum: `pid`, `duration`, `waiting`, `lid` | `duration` от часа, `waiting` не пусто |
| `Lock` | кто кого блокирует: заблокированные `pid` и режимы, блокирующий `pid` и его приложение | любая строка — блокировка есть |
| `CTL Today Errors` | упавшие сегодня шаги: `res`, `try`, `msg`, `last_ok` — когда поток последний раз был успешен | повторы одного потока, давний `last_ok` |
| `CTL Today No data` / `Long` / `Done` / `Ok` / `Fcts` | шаги дня: без данных / долгие / закончившиеся / успешные / витрины `fcts` | в `Long` — `duration`; в `No data` — ожидаемо ли отсутствие данных |
| `CTL Not scheduled` | потоки без расписания в CTL | неожиданные имена — сняты с расписания случайно? |

### `pc1080.mail_ctl_status` — «CTL Status», сводка по кодам и полный список

| Раздел | Что в нём |
|---|---|
| `CTL Today` | по категории и префиксу имени: `wf_cnt`, `sum_time`/`min`/`max`/`avg_dur`, счётчики по кодам `res` (раздел 3) |
| `CTL All Active` | все активные загрузки (сотни строк): статус, сколько в нём, условие запуска |
| `CTL All WF` | все потоки дерева: `scheduled`, `deleted`, связанные сущности, параметры |
| `CTL All Today` | все шаги дня: время, длительность, `res`, `try`, `msg` |
| `CTL Not scheduled`, `Ztest Errors` | потоки без расписания; ошибки Z-теста за сутки |

`CTL All Active` и `CTL All WF` на проде по ~500 строк: в CTL они не помещаются, `ctl_report`
отдаёт их из полной копии — 50 строк и `rows_total`. Не пересказывай списком — считай и
группируй (по статусу, категории, возрасту).

### `pc1080.mail_ctl_work_load_report` — нагрузка за вчера

- `CTL Yesterday Work Load` — 24 строки (`n` — час), в каждой шесть 10-минутных слотов:
  `cnt_MM` — сколько шагов шло в слоте, `rate_MM` — доля занятости слота (1.0 — всё время
  слота шагов было столько, сколько максимум за сутки). Ищи часы с высокой `rate` — окно пика.
- `CTL Yesterday Summary / Errors / Long / SDPUE` — итоги, ошибки, долгие шаги за вчера.
- `HR_Data Lake Speed / Skew / Ratio / Uncompress` — рост, перекос и сжатие таблиц
  Greenplum (только на Greenplum; на стенде пусто).

### Остальные

- `mail_ztest_report` — `Ztest Summary` (итог Z-тестов по объектам), `Actual_date repeat` /
  `Row_count repeat` (дата данных или число строк не меняются несколько прогонов подряд —
  данные «застыли»), `Ztest Details`.
- `mail_sdpue_report` — `SDPUE Last`: последняя загрузка каждого UE-потока — `wait_time`
  (сколько ждала), `run_time`, `status`, `rows_count`, `sum_len`, `retry`; `SDPUE Errors`.
- `mail_informatica_report` — последние загрузки и журнал Informatica.
- `mail_ctl_alerts` — раздел 4.

## 3. Как читать значения (и что было бы цветом в письме)

Колонки `res` и счётчики `cnt_*` — коды `pr_swf_start_ctl` (подробно — `ctl-worker`, раздел 4):

| Код / колонка | Цвет в письме | Что значит |
|---|---|---|
| `1` / `cnt_ok` | зелёный (lime) | успех |
| `0` / `cnt_no_data` | бледно-жёлтый | нет данных — штатно, если источник не обновлялся |
| `-1` / `cnt_empty` | жёлтый | пусто |
| `-2` / `cnt_canceled` | розовый | упёрлись в таймаут или отменили |
| `-3` / `cnt_expired` | фуксия | истёк срок ожидания событий |
| `-4` / `cnt_uniq` | голубой | не прошла проверка уникальности |
| `-5` / `cnt_ztest` | фиолетовый | проверка качества (Z-тест, расхождение строк) |
| `-7` / `cnt_ctl_err` | серебристый | исключение в процедуре потока |
| `-8` / `cnt_pxf_err` | оранжевый | ошибка PXF (внешний источник) |
| `-9` / `cnt_error` | лосось (красный) | прочие ошибки |

Возраст: розовый — старше суток, красный — старше двух. `CTL Old and Working` — загрузки,
которые идут дольше суток; `GP Working` — что сейчас выполняется в Greenplum; `Lock` — кто
кого ждёт (блокирующий и заблокированный процесс).

## 4. SLA-алерты (`mail_ctl_alerts`)

Правило потока — параметры `wf_alert` (когда), `wf_alert_data` (что сверять), `wf_alert_group`
(кому). Строка отчёта: время, поток, группа, правило, период, `since` (когда проблема
началась), `closed` (заполнено — алерт снят), `msg` (причина). `res` загрузки рассыльщика
`-6` — были новые алерты, CTL разослал письмо; `1` — новых нет.

- Строка закрыта (`closed` заполнено) — в письме зелёная, проблемы уже нет.
- «никогда» в `msg` — данных по объекту нет вовсе или поток ни разу не отдавал статистику:
  почти всегда ошибка в самом правиле (не тот `obj` или `stat`) — **Чьё:** владелец потока.
- `since` старше 1 / 3 / 5 суток — жёлтый / розовый / красный период.
- Алерты одного потока — `ctl_alerts("<поток>")`; дальше — «что с потоком X» (`ctl-worker` 2а).

## 5. Чего не делать

- Не пересказывать весь отчёт построчно: раздел, счёт, главное.
- Не запускать отчёт заново (`trigger_dag`, `clear`) — отчёт строится по расписанию CTL.
- Не придумывать цвет, которого нет в значениях: цвет — следствие кода и возраста.
- Не выдавать отчёт с альфы за сигму и наоборот: у каждого контура свой CTL и свои отчёты.

## 6. Что проверить человеку

- Письмо отчёта и его адресатов — `statusNotifications` потока в CTL.
- Сам SQL отчёта — в Greenplum, схема `s_grnplm_vd_hr_edp_srv_wf`, функция из раздела 2;
  журнал отчётов — `tb_swf_mail_log`, открытые SLA-алерты — `tb_ctl_alerts`.

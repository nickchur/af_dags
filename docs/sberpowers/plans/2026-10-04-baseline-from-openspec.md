# План: baseline-спеки из спецификаций OpenSpec

> Исполняется скиллом execute: свежий исполнитель на задачу; задача видит
> только собственный текст. Шаги — чекбоксы `- [ ]`.

**Спека:** отдельной delta-спеки нет — меняется формат документов, а не поведение системы.
Источник — `openspec/specs/<возможность>/spec.md` (8 возможностей, 176 требований).
**Цель:** у каждой возможности есть `docs/sberpowers/specs/<возможность>-baseline.md`, в
котором ни одно требование, сценарий и строка «Происхождения» не потеряны.
**Архитектура:** одна задача — одна возможность; исполнитель переводит документ по шаблону,
проверка `.claude/scripts/check_baseline.py <возможность>` сверяет полноту механически,
смысл формулировок проверяет ревью. Старые спецификации удаляются отдельно, после всех задач.

## Глобальные ограничения

- Шаблон — `docs/sberpowers/specs/TEMPLATE-spec.md`: разделы «Назначение», «Требования»,
  «Ограничения и контракты», «Non-goals», «Критерии приёмки», «Traceability» — все, с этими
  заголовками; HTML-комментарии шаблона в результат не переносятся.
- Шапка: `- Дата: 2026-10-04`, `- Статус: реализована`,
  `- Источник: openspec/specs/<возможность>/spec.md, перевод 2026-10-04`.
- «Назначение» — из раздела `## Purpose` исходника, по смыслу без потерь.
- Требование: `- **REQ-<возможность>-NN** — **<название>.** <наблюдаемая истина>`, где
  `<возможность>` — имя каталога в `openspec/specs/` (`ctl-worker`, `tools`, …), NN — номер с
  01 подряд в порядке `### Requirement:` исходника, `<название>` — текст после
  `### Requirement:` дословно, `<наблюдаемая истина>` — содержание требования по-русски,
  без «SHALL/MUST»: что видно снаружи, когда требование выполнено.
- Каждый `#### Scenario:` исходника — отдельная строка в «Критериях приёмки»:
  `| REQ-<возможность>-NN | <название сценария>: дано … → действие … → результат … |`.
  Сценарии не сливаются и не выбрасываются.
- Таблица «Происхождение» исходника (если есть) переносится в «Ограничения и контракты»
  строками `- Происхождение (REQ-<возможность>-NN): <откуда> Пересматривать: <когда>`, где
  «откуда» и «когда» — ячейки таблицы **дословно**, со всеми путями, датами и кодом.
- Прочие ограничения, контракты, форматы и константы из текста требований, которые не
  помещаются в одну «истину», — в «Ограничения и контракты» списком, с REQ-ID в скобках.
- «Non-goals» — то, что исходник прямо называет вне рамок; если такого нет — строка
  «В исходной спецификации границы не записаны; дополняется при первой дельте».
- Traceability: строка на каждый REQ, колонки «Задачи плана» и «Тесты» — `—`,
  статус `реализовано`.
- Меняется только `docs/sberpowers/specs/<возможность>-baseline.md`; исходник не трогать.
- Документ уезжает в корпоративный репозиторий: без упоминаний внешних сервисов, агентов,
  номеров PR и зеркал.

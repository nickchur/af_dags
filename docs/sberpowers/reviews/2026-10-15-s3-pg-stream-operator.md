# Ревью: HrpS3ToPgStreamOperator — потоковая загрузка S3 → GP/PG
*2026-10-15 · plugins/pg_stream.py v0.9, tools/test_pg_stream.py v0.9, раздел tools/readme.md*

## Итог

Код проверили три независимых ревьюера: две модели по обеим осям и отдельный поиск молча проглоченных
ошибок. Каждая находка сверена с кодом и стендом, принятые исправлены, даг перепрогнан на обоих
подключениях: PostgreSQL 16 (`cap_gp_etl`) и Greenplum 6.25.4 (`gp6-stand`).

На стенде не проверяемо (контур — PostgreSQL 15.5, Greenplum 6.25.3): текст NOTICE отбраковки GP
(`found N data formatting errors`), `jsonb_populate_record` на GP для вложенных объектов и массивов,
поведение через пулер соединений.

## Принято и исправлено

- **Ошибка разбора маскировалась под `QueryCanceled`.** Исключение внутри `read()` psycopg2 отдаёт как
  `QueryCanceled: error in .read() call` — тот же SQLSTATE, что у `statement_timeout`. Теперь поднимается
  исходное (`ValueError`, `UnicodeDecodeError`, ошибка gzip); сценарии дага проверяют тип.
- **Нет объекта в S3.** `S3Hook.get_key` не возвращает `None`, а бросает `ClientError 404` — ветка
  `AirflowFailException` была мёртвой, таск уходил в повторы без имени ключа. 404 → `AirflowFailException`
  с ключом; новый сценарий.
- **JSON Lines без предела длины строки.** Массив в одну строку под именем `.jsonl` рос в буфере до OOM.
  Строка длиннее 64 млн символов — ошибка с номером строки.
- **Битый элемент JSON-массива в середине файла** копил буфер до конца файла и давал «файл оборван». Ошибка
  раньше конца буфера (кроме незакрытой строки) — сразу «битый элемент» с позицией; самопроверка гоняет
  разрезы по 1…7 символов, в том числе по `\uXXXX`.
- **Регистр имени `tmp_table`.** Блокировка брала oid из строки без кавычек (`s.Raw` → `s.raw`), запись —
  из имени в кавычках. Теперь `to_regclass` от того же разобранного имени; нет таблицы — «таблицы нет» до S3.
  Новые сценарии: имя с заглавными, несуществующая таблица.
- **Откат на оборванном сеансе** подменял исходную ошибку `InterfaceError` — исходная остаётся ошибкой таска.
- **Сбой второй транзакции.** Лог уверял «приёмник не изменён», хотя при сбое самого commit исход неизвестен;
  теперь «вторая транзакция не прошла, сырьё — в `tmp_table` до повтора задачи».
- **`pg_advisory_unlock` вернул false** (другой серверный сеанс — пулер транзакций) — предупреждение.
- **`rows_rejected < 0`** (счёт строк csv по кавычкам разошёлся с COPY) писался как «не загружено -1» —
  теперь отдельное предупреждение о расхождении счёта.
- **NOTICE отбраковки GP** мог быть отрезан `client_min_messages`; при `REJECT LIMIT` ставится `notice`,
  регулярка — без учёта регистра.
- **UTF-8 BOM** — снимается и у JSON, и у CSV; сценарий CSV с BOM без заголовка.
- **Пустой zip** — предупреждение; **отрицательный `statement_timeout`** — ошибка параметра.
- Шапка модуля: таблица параметров, пример, ограничения (потолок элемента, zip без вложенного сжатия).

## Отклонено

- «`SAVEPOINT` не поддерживается Greenplum, `truncate='auto'` неработоспособен» — сценарии `auto` и
  `auto-busy` зелёные на GP 6.25.4.
- «Без `stream_unzip` нужна ошибка «zip не поддерживается»» — `s3_utils` импортирует пакет на верхнем
  уровне, он есть в образах; без него модуль не загрузился бы вовсе.
- «Утечка advisory-блокировки при сбое commit первой транзакции» — соединение закрывается в конце
  `execute`, сеансовая блокировка уходит вместе с ним.
- «`truncate='auto'` на GP может вернуть не 55P03» — на стенде GP отвечает `LockNotAvailable`.
- «`root` должен допускать соседние ключи» — по спеке ключ в конверте единственный (REQ-plugins-20).
- «Колонка с `default`, встреченная не во всех элементах, получает NULL» — по REQ-plugins-27 `default`
  получают колонки, которые оператор не заполняет; встреченный ключ — заполняемая колонка. Решение
  15.10.2026, уточнено в REQ-plugins-27 и шапке модуля.
- «`unmapped` / `defaulted` пусты для CSV» — у CSV колонки файла = колонки таблицы (REQ-plugins-23).
- «Повтор задачи стирает сырьё `tmp_table`» — решение 15.10.2026: повтор перечитывает тот же файл из S3,
  в логе и шапке уточнено «до повтора задачи».
- Мелочи без изменения: имена в zip в cp1251 (cp866 декодирует любые байты), заголовок CSV длиннее 1 МБ,
  `source` CSV из первого файла архива, служебные файлы архиваторов в zip (явная ошибка формата лучше
  молчаливого пропуска), `SET LOCAL` не действует на `pg_advisory_unlock`, лишний `select version()`.

## Пробелы тестов, оставленные

## Дополнение 16.10.2026: `GeneratorExit` в `guard()`

Найдено при переносе на Airflow 3. Когда база обрывает COPY посреди потока, генератор закрывается, и
`GeneratorExit` попадал в `failed`; `raise failed[0]` поднимал его вместо ошибки базы — причина
падения терялась. Исправлено: `GeneratorExit` пробрасывается до общего перехвата. Проверено модельно
(потребитель на C, как `copy_expert`); живой обрыв COPY на psycopg2 на стенде не прогонялся.

# Свод ревью: `ctl_api` читает `gp_pool` раз в минуту

- Спека: `docs/sberpowers/specs/2026-10-19-ctl-api-gp-pool-once.md` (REQ-ctl-api-01, 02)
- Ревьюеры: DeepSeek v4-pro, agy gemini-3.8-flash-high (дифф `3c63a03`). Оба: REQ выполнены.

| Находка | Кто | Решение |
|---|---|---|
| Гонка потоков в `_gp_pool_open` (нет блокировки) | оба | Отклонено: `ctl_api` нигде не зовут из потоков; `_lock` в модуле — только для `rate_limit`; `concurrent.futures` в стеке падения — внутренности tenacity |
| Сбой чтения `gp_pool` логируется как «ошибка записи журнала» | DeepSeek | Принято: отдельное сообщение и заметка к задаче |
| `pool_size` вернёт `None` → `TypeError` | agy | Отклонено: `af_meta.pool_size` всегда `int`, нет пула — 0 |
| Нет теста, что без журнала (`gp_log=False`, POST, `tmpl`, `statval`) метабаза не опрашивается | оба | Принято: `test_no_journal_no_metabase` |
| Тест сбоя не проверяет запись в лог | agy | Принято: проверка лога и заметки |
| Docstring `_gp_pool_open` «исключение уходит наверх» противоречит поведению | DeepSeek | Отклонено: из `_gp_pool_open` исключение действительно уходит, ловит его `ctl_api` |

Решение пользователя по REQ-ctl-api-02 (19.10): при сбое метабазы журнал пропускать, пропуск показывать
заметкой к задаче (вариант «1»), а не ронять задачу.

Стенд AF3: тесты 7 passed; ран `CTL.HR_Data.loader` 14:29 UTC на новом коде — success, GET к эмулятору ~0,1 с.

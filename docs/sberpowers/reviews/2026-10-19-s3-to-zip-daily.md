# Ревью: `tools_s3_to_zip` — ежедневно, массив src, add_ts, сохранение параметров (2026-10-19)

Ревьюеры: DeepSeek `deepseek-v4-pro` (opencode), agy `gemini-3.8-flash-high`. Вход: delta-спека + дифф от
`af/develop_3` + полный текст `s3_to_zip`. Оба: все REQ выполнены, блокирующих нет. Каждую находку проверил сам.

## Принято

| Находка | Кто | Что сделано |
|---|---|---|
| Номер имени конфликтует с src, чьё имя уже `<x>_N` (`logs, logs, logs_2` → два `logs_2`) | оба | номер — до первого свободного с учётом имён всех src; тест `logs, logs_3, logs_2` |
| «Вчера» от `now()` внутри таска: Clear вчерашнего рана на следующий день архивирует другие сутки | agy (DS — инфо) | `_jobs(params, dag_run.run_after)`: слот у рана по расписанию, время запуска у ручного; Clear не меняет; проверено на стенде |
| Регулярка отмены хвостов чувствительна к регистру `.ZIP` | agy | `re.IGNORECASE`; в тест добавлен `logs.ZIP` |
| Подпись экземпляра ≠ имя архива при `dst` на `.zip` | оба | при `dst` на `.zip` имя берётся из ключа; тест |
| `src` строкой в переменной (ручная правка) итерируется посимвольно | DS | строка оборачивается в список; тест |

## Отклонено

| Находка | Кто | Почему |
|---|---|---|
| `save_params` осядет в переменной | agy | `store_params` снимает флаг сам; на стенде в переменной его нет |
| Нет теста импорта DAG / теста сохранения параметров | оба | DagBag на стенде; механика сохранения общая с `log_cleanup`, проверена раном `daily_save_3` |
| Пустой `src` по умолчанию при логах не в S3 | DS | форма справедливо требует указать путь |
| Хрупкость извлечения `_jobs` через ast | DS | принятый в репо приём (`test_conn_facts.py`) |
| «Уже есть» раньше skip при `add_ts=False` и пустом дне | DS | с фиксированным именем ежедневный ран и так требует `replace=True`; порядок — базовый REQ-06 |
| Регулярка ждёт только формат метки дага | agy | метку формирует сам даг |

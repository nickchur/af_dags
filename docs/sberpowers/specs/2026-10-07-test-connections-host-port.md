## Мотивация

С переносом списка подключений в проверку доступности (E360-6385) из отчётов пропали хосты и
порты: прежний аудит подключений показывал их таблицей и отдавал в XCom. Без адреса по упавшей
проверке не видно, куда не достучались, а у S3 и Kafka адреса не было и раньше — он лежит в extra.

## ADDED — новое поведение

- **REQ-tools-42** — **Адрес подключения определяется одним правилом и виден везде одинаково.**
  У каждого подключения проверки доступности есть адрес — хост и порт. Хост заполнен в
  подключении — адрес берётся из хоста и порта подключения как есть. Хост пуст — адрес берётся из
  первого непустого параметра extra по порядку `endpoint_url`, `bootstrap.servers`. Значение из
  extra без запятой раскладывается на хост и порт (вид `схема://хост:порт` или `хост:порт`); порта
  в значении нет — порт пуст. Значение с запятой даёт хосты без портов через запятую и порт
  первого из них (у первого порта нет — порт пуст). Адреса нет нигде — хост и порт пусты. Один и
  тот же адрес показывается в подписи задачи проверки, в строке сводки, в логе сбора списка, в XCom
  и в Variable.

## MODIFIED — изменённое поведение

## Ограничения и контракты

- XCom `connections` повторяет форму, которую отдавал прежний аудит подключений и которую держит
  Variable `local_connections`: `{тип: [{conn_id, host, port, schema, description}]}`, подключения
  ClickHouse под типом `sqlite` показаны под типом `clickhouse`. Отсутствующее описание — `No
  description`.
- XCom-бэкенд платформенного ядра отбрасывает значения длиннее 500 элементов и больше
  `max_xcom_size`: словарь по типам — десяток ключей, предел не задевается; список проверок — по
  элементу на подключение, как и до изменения.
- Variable `local_connections` читает ручная проверка Kafka, и только имена подключений; смена
  адресов у S3 и Kafka её не затрагивает.
- В адрес, лог, XCom и Variable не попадают логин, пароль и прочие параметры extra — только хост и
  порт.
- Подпись экземпляра не длиннее 250 символов — предел колонки подписи в метабазе Airflow, сам
  Airflow значение не обрезает и сохранение экземпляра падает; длиннее — обрезается с «…»
  (REQ-tools-02).
- Непригодный адрес из extra даёт пустой адрес и предупреждение в логе таска сбора с именем
  подключения, ключом extra и текстом причины (само значение в лог не пишется), а не падение
  сбора и не частичный адрес (REQ-tools-42). Непригодный — extra не объект; значение ключа не
  строка; не разбирается как адрес; порт не число или вне 1–65535; хотя бы один хост пуст.
  Причина в предупреждении — постоянный текст, без фрагментов значения.
  Пустая строка и `null` в ключе непригодными не считаются — это отсутствие значения, берётся
  следующий ключ. Порт проверяется у каждого хоста списка, показывается порт первого.
- Разбор `хост1,хост2` + порт первого повторяет формат, который secret backend сам строит для
  Postgres с несколькими хостами; разные порты у хостов одного значения показываются портом первого.

## Non-goals

- Результат задачи проверки (её XCom) не меняется: адрес по имени подключения есть в
  `connections`, дубль не нужен.
- Таблица адресов в заметке таска сбора не возвращается: заметка ограничена 1000 символами, на
  сотне подключений таблица обрезается.
- Отдельный DAG аудита подключений не восстанавливается.
- Адрес не проверяется и не нормализуется (резолв, схема, порт по умолчанию для схемы) — только
  показывается.
- Ключи extra, кроме `endpoint_url` и `bootstrap.servers`, адресом не считаются; новый ключ —
  отдельное изменение.

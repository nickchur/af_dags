# Delta-спека: оператор HrpS3ToPgStreamOperator (S3 → GP/PG, CSV и JSON)

- Дата: 2026-10-15
- Статус: подтверждена
- Baseline: `docs/sberpowers/specs/plugins-baseline.md` (новая возможность в `plugins`, нумерация продолжает baseline)
- Источник: discover `discovery/2026-10-15-s3-to-gp-operator.md`, grill `discovery/2026-10-15-s3-to-gp-operator-decisions.md`

## Мотивация

Файлы из S3 (CSV, JSON-массив, в том числе под ключом, JSON Lines) нужно грузить в таблицу Greenplum
или PostgreSQL одним оператором, потоково и одной транзакцией. Сейчас JSON из дага не грузится вовсе,
а CSV — только кодом `ctl_worker` (альфа) или `HrpS3ToPostgresOperator2` с промежуточными коммитами.
Оператор — для баз, где пишущая транзакция не ограничена или предел несущественен.

## ADDED — новое поведение

### Подключение и транзакция

- **REQ-plugins-07** — **Один объект S3 в одну таблицу GP или PG.** Оператор `HrpS3ToPgStreamOperator` грузит один объект S3 (`bucket`, `s3_key`;
  `s3_key` шаблонизируется) в одну таблицу (`table`, со схемой или без) базы по `conn_id`; одна и та же
  настройка работает и на Greenplum, и на PostgreSQL. Подключения: S3 — `s3_conn_id`, база — `conn_id`.
- **REQ-plugins-08** — **Загрузка — одна транзакция.** Вся загрузка (усечение, все строки, служебные шаги) — одна транзакция: после
  ошибки на любом шаге таблица приёмника в том же состоянии, что до запуска (включая данные, удалённые усечением).
- **REQ-plugins-09** — **Потоковое чтение.** Файл не читается в память целиком: пиковая память процесса не растёт с размером
  файла (ограничена куском чтения и самым большим элементом).
- **REQ-plugins-10** — **Таймаут запроса.** На сессию ставится `statement_timeout` = параметр `statement_timeout` в минутах,
  по умолчанию 240 (4 часа) для GP и PG; `0` — без предела.
- **REQ-plugins-11** — **Итог загрузки в лог и XCom.** По окончании оператор пишет в лог число загруженных строк
  и возвращает (XCom `return_value`) словарь: `rows` — число строк; `files` — обработанные файлы (для zip —
  имена внутри архива); `target` — колонки приёмника с типами короткими системными именами (`int4`,
  `varchar`, `timestamp` — как `srv_wf.pr_get_format_type`, по oid из `select * … limit 0`); `source` —
  поля источника: для JSON ключи объекта `item` с типами JSON (`string`, `number`, `boolean`, `object`,
  `array`, `null`, разные — через `|`), для CSV с заголовком — имена из заголовка с типом `text`, без
  заголовка — `{}`; `unmapped` — ключи без колонки; `defaulted` — колонки, ни разу не заполненные (взят
  `default`). `source` — не больше 500 ключей, сверх — `source_truncated: true`.

### Усечение

- **REQ-plugins-12** — **Без усечения по умолчанию.** `truncate=None` (по умолчанию): строки приёмника не удаляются.
- **REQ-plugins-13** — **Жёсткое усечение.** `truncate='hard'`: приёмник очищается `TRUNCATE` (ждёт блокировку, если таблица занята).
- **REQ-plugins-14** — **Мягкое усечение.** `truncate='soft'`: приёмник очищается `DELETE` без исключительной блокировки:
  читатели видят прежние данные до конца загрузки.
- **REQ-plugins-15** — **Автоматический выбор усечения.** `truncate='auto'`: если исключительная блокировка доступна сразу — `TRUNCATE`, если
  таблица занята — `DELETE`; выбранный способ пишется в лог. Работает на GP и PG без функций схемы `srv_wf`.
- **REQ-plugins-16** — **Проверка значения truncate.** Иное значение `truncate` — ошибка до любого обращения к S3 и базе.

### Формат и сжатие

- **REQ-plugins-17** — **Формат по параметру или расширению.** `format` = `csv` | `json` | `jsonl` | `auto` (по умолчанию). `auto` выбирает по
  расширению ключа после снятия расширения сжатия: `.csv` → csv, `.json` → json, `.jsonl`/`.ndjson` → jsonl;
  иное — ошибка с именем ключа.
- **REQ-plugins-18** — **Сжатие gz и zip.** Ключ на `.gz` распаковывается потоково. Ключ на `.zip` грузится всеми файлами
  архива по очереди в ту же таблицу и ту же транзакцию, формат `auto` определяется по имени файла в архиве
  (требование желательное: при невозможности — `.zip` даёт понятную ошибку «zip не поддерживается»).
- **REQ-plugins-19** — **CSV с опциями COPY.** `csv`: строки идут `COPY` в приёмник с опциями из параметра `options`
  (по умолчанию `CSV HEADER DELIMITER ','`).

### JSON

- **REQ-plugins-20** — **JSON-массив и ключ root.** `json`: файл — массив элементов на верхнем уровне или под ключом верхнего объекта
  `root` (`{"data": [...]}` при `root='data'`). Битый JSON (лишняя/пропущенная запятая, хвост после массива,
  обрыв файла, нет ключа `root`) — ошибка, ничего не загружено.
- **REQ-plugins-21** — **JSON Lines.** `jsonl`: каждая непустая строка — один элемент; битая строка — ошибка с номером строки.
- **REQ-plugins-22** — **Путь item внутри элемента.** `item` — путь к объекту внутри элемента: строка через точку любой глубины
  (`payload`, `payload.value`) или список ключей (для ключа с точкой в имени); по умолчанию весь элемент.
  Нет ключа на уровне или уровень — не объект: ошибка с номером элемента и уровнем пути.
- **REQ-plugins-23** — **Способ записи по составу приёмника.** Способ записи определяется по составу приёмника (`select * … limit 0`): если в
  приёмнике одна колонка (не считая `file_name_column`) типа `json`/`jsonb` — объект `item` пишется в неё
  целиком; иначе объект раскладывается по колонкам приёмника.
- **REQ-plugins-24** — **Сопоставление ключей с колонками.** Раскладка: ключи сопоставляются с колонками без учёта регистра; колонка без
  ключа получает `NULL`; ключ без колонки отбрасывается, а список таких ключей пишется в лог один раз;
  два ключа одного объекта, различающиеся только регистром, — ошибка.
- **REQ-plugins-25** — **Неприводимое значение роняет загрузку.** Значение, не приводимое к типу колонки, роняет загрузку целиком с сообщением
  базы (значение и тип).

### Служебные колонки

- **REQ-plugins-26** — **Колонка с именем файла.** `file_name_column` (по умолчанию `None`): если задан, каждая строка получает в этой
  колонке ключ S3, для файла из zip — `<ключ>/<имя в архиве>`; работает для csv, json и jsonl.
- **REQ-plugins-27** — **Значения по умолчанию из DDL.** Колонки приёмника, не заполняемые оператором, получают значения по умолчанию из
  DDL (например, время загрузки — `default now()`).

## Ограничения и контракты

- Python 3.10–3.12, без новых зависимостей (`ijson` в образах нет; `stream_unzip` есть на альфе — на сигме
  проверить, иначе zip только там, где он есть).
- Модуль в `plugins/` с двойным импортом (fallback `CI06932748.tools`); на сигме оператор упадёт на
  белом списке операторов, пока не перенесён в etl-core и не внесён в `allowed_operators.txt`.
- Права — забота `conn_id`; оператор не меняет структуру приёмника и не зовёт функций схемы `srv_wf`.
- Синтаксис GP6 (COPY, `jsonb_populate_record`, временные таблицы с `distributed randomly`) на стенде PG16
  не проверяем — отдельная проверка на контуре.
- Параметры оператора (контракт):
  `s3_key`, `table`, `bucket=None`, `s3_conn_id='s3'`, `conn_id='cap_gp_etl'`, `format='auto'`,
  `root=None`, `item=None`, `options="CSV HEADER DELIMITER ','"`, `truncate=None`, `file_name_column=None`,
  `statement_timeout=240`.
- Строки идут в базу одной командой `COPY` на файл (для zip — на файл архива): генератор строк обёрнут в
  объект с `read()`, `copy_expert` тянет его кусками. Отвергнуто: пачки по N строк отдельными `COPY` (как в
  тестовом даге `tools_test_json_pg`) — лишние команды и параметр `batch`, который нечем выбирать.

## Non-goals

- Маски, перебор нескольких ключей, `.done`, перенос в `tfs-archive`/`tfs-errors`, статусы CTL — остаются в `run_tfs`.
- Подключение оператора к `run_tfs` — отдельная задача после проверки на контуре.
- Промежуточные коммиты и инкарнации (`<table>_0/1`) — это `HrpS3ToPostgresOperator2`.
- Вложенный `root` (`a.b`) — по запросу; сейчас один уровень.
- Номер элемента в служебной колонке, таблица отбраковки, `NULL` вместо неприводимых значений.
- Перенос в etl-core и строка в `allowed_operators.txt` — второй этап.

## Критерии приёмки

| REQ-ID | Сценарий проверки |
|---|---|
| REQ-plugins-07 | Даг с оператором на стенде PG: файл из S3 загружен в таблицу; тот же даг с `conn_id` GP на контуре — тоже |
| REQ-plugins-08 | Таблица с 5 строками, `truncate='hard'`, в файле на 1000-м элементе битое значение → таск красный, в таблице те же 5 строк |
| REQ-plugins-09 | Файл 1 ГБ грузится при пике RSS таска, сравнимом с файлом 10 МБ (разница < 200 МБ) |
| REQ-plugins-10 | В логе таска `statement_timeout` = 240 мин без параметра и заданное значение с параметром |
| REQ-plugins-11 | Загрузка в пустую таблицу без усечения: `return_value.rows` = `count(*)` приёмника; `target` = колонки с `int4`/`text`/`date`…; JSON с ключами `employeeId` (числа), `extra` (объект) → `source` = `{"employeeId": "number", "extra": "object"}`, `unmapped` = `["extra"]`, `defaulted` содержит `load_dttm`; 600 разных ключей → в `source` 500 и `source_truncated: true` |
| REQ-plugins-12 | Две загрузки одного файла без `truncate` → строк вдвое больше |
| REQ-plugins-13 | `truncate='hard'`: после загрузки в таблице только строки файла |
| REQ-plugins-14 | `truncate='soft'`: во время загрузки другой сеанс читает таблицу без ожидания и видит старые строки; после — только строки файла |
| REQ-plugins-15 | `truncate='auto'`: без конкурентов — в логе `truncate`; при открытой чужой транзакции с `lock … in access share mode` — в логе `delete`, загрузка не ждёт |
| REQ-plugins-16 | `truncate='yes'` → ошибка параметра, в S3 и базе обращений нет |
| REQ-plugins-17 | Ключи `.csv`, `.json.gz`, `.ndjson` грузятся без `format`; ключ `.txt` без `format` → ошибка с именем ключа |
| REQ-plugins-18 | `.json.gz` грузится потоково; zip с двумя csv → строки обоих в таблице (или ошибка «zip не поддерживается») |
| REQ-plugins-19 | CSV с `;` и `options="CSV HEADER DELIMITER ';'"` грузится; без `options` — по умолчанию `,` с заголовком |
| REQ-plugins-20 | Файл ИФТ `{"data": [...]}` с `root='data'` → 4 строки; тот же без `root` → ошибка; файл с лишней запятой → ошибка, строк 0 |
| REQ-plugins-21 | jsonl с 3 строками и пустой строкой в конце → 3 строки; битая 2-я строка → ошибка с «строка 2» |
| REQ-plugins-22 | Файл ИФТ, `item='payload'` → в jsonb-приёмнике нет ключа `schema`; `item='payload.nope'` → ошибка с номером элемента и `nope` |
| REQ-plugins-23 | Приёмник `(j jsonb)` → элемент целиком в `j`; приёмник с колонками → значения по колонкам |
| REQ-plugins-24 | Ключ `employeeId` → колонка `employeeid`; ключ `extra` без колонки → в логе `extra`, загрузка зелёная; колонка без ключа → `NULL`; объект `{"a":1,"A":2}` → ошибка |
| REQ-plugins-25 | Колонка `date`, значение `"31.12.2026"` → таск красный, в ошибке значение и тип, строк 0 |
| REQ-plugins-26 | `file_name_column='src'` → у всех строк `src` = ключ S3 (для csv, json, jsonl) |
| REQ-plugins-27 | Колонка `load_dttm default now()` не в файле → заполнена временем загрузки |

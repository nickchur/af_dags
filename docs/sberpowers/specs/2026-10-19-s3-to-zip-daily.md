- Baseline: docs/sberpowers/specs/2026-10-19-s3-to-zip.md (REQ-s3zip-01…11)
- Источник: grill 19.10.2026 («даг ежедневный, логи раз в сутки, по умолчанию за сутки; src — массив; параметр TS к имени; сохранение параметров»)

## Мотивация

Архив логов нужен регулярно, а не только руками: раз в сутки, за вчерашний день. Источников может быть несколько
(логи задач, `ctl/`, `docs/` бакета логов) — по архиву на каждый. Настройки (пути, расписание, лимит) должны жить в
переменной, как у соседних служебных дагов, чтобы менять их из формы запуска без выкладки кода.

## MODIFIED

- **REQ-s3zip-01** — **src — массив путей.** Параметр `src` — список строк `conn_id://бакет/путь` (минимум одна),
  по умолчанию `[<префикс логов задач из [logging]>]`. **На каждый src — отдельный архив** в `dst`; каждый — отдельный
  экземпляр таска (свои заметка, ретраи, падение). `dst` — одна строка; при нескольких src он обязан быть папкой —
  `dst` на `.zip` при двух и более src — красный ран до записи.
- **REQ-s3zip-03** — **даты — по MSK, по умолчанию вчера.** `date_from` / `date_to` (`YYYY-MM-DD`, обе включительно)
  сравниваются с `LastModified`, переведённым в MSK (UTC+3). Оба пусто — вчерашняя дата MSK от времени старта рана
  (и по расписанию, и вручную). Задана одна — вторая без границы. Весь объём — явным диапазоном дат.
- **REQ-s3zip-04** — **предохранитель и пустой отбор.** `max_size_gb` — на каждый архив отдельно. Пустой отбор у src —
  пропуск экземпляра (skipped, «нечего архивировать»), а не падение: при ежедневном запуске пустой день — норма.
- **REQ-s3zip-05** — **имя архива и `add_ts`.** Имя — `<последняя папка src>`; совпавшие у разных src имена получают
  номер по порядку (`airflow-logs`, `airflow-logs_2`). `add_ts=True` (по умолчанию) — к имени добавляется
  `_YYYYMMDD_HHMMSS` (UTC, старт рана; одна метка на ран), в том числе перед `.zip`, если `dst` — ключ архива.
  `add_ts=False` — `<имя>.zip` в папке `dst` или ключ `dst` как есть; повторный запуск с тем же именем упирается в
  REQ-s3zip-06 (`replace`).
- **REQ-s3zip-10** — **оформление дага.** Расписание по умолчанию — ежедневно `30 1 * * *` MSK, параметр `schedule`
  (cron или пресет; пусто — только вручную). Экземпляры архивации идут по одному (`max_active_tasks=1`): нагрузка на
  воркер и S3 как от одного архива. Пул, приоритет, колбэки ошибок — как у соседних служебных дагов (`tools`).
  `is_paused_upon_creation=True` сохраняется.
- **REQ-s3zip-11** — **брошенные части — только свои.** Отменяются незавершённые загрузки в папке архива, чей ключ
  начинается с имени архива этого src (`<имя>_…zip` / `<имя>.zip`): экземпляры одного рана и разные src не трогают
  загрузки друг друга.

## ADDED

- **REQ-s3zip-12** — **сохранение параметров.** Значения формы по умолчанию берутся из переменной
  `tools_s3_to_zip_params`, код — запасной вариант. Галочка `save_params` (разовая, в переменную не пишется) сохраняет
  параметры запуска первым таском `params`; без галочки или без изменений — `params` пропускается, архивация идёт.
  `date_from` / `date_to` — разовые, в переменную не сохраняются: иначе ежедневный ран застынет на одной дате.
  Негодное `schedule` — падение `params`, переменная не меняется; битое значение в переменной не роняет разбор дага
  (берётся расписание из кода).

## Non-goals

- Несколько src в одном архиве.
- Догон пропущенных суток (catchup): ран архивирует только вчера; пропущенное — вручную диапазоном дат.
- Пункт `AbortIncompleteMultipartUpload` в правиле хранения — по-прежнему в бэклоге.
- Перенос в AF2 (`master`).

## Критерии приёмки

- Стенд AF3: ран без параметров (src по умолчанию) — архив `airflow-logs_<TS>.zip`, в нём только объекты с
  LastModified вчера по MSK; заметка на экземпляре.
- Стенд AF3: `src` из двух путей с одинаковой последней папкой — два архива, `<имя>_<TS>.zip` и `<имя>_2_<TS>.zip`.
- Стенд AF3: src без объектов за вчера — экземпляр skipped, ран зелёный.
- Стенд AF3: `save_params=True` с другим `max_size_gb` и `date_from` — в переменной новый `max_size_gb`, дат нет;
  форма следующего запуска показывает новое значение.
- Тесты без сети: имена с номерами и `add_ts`; вчера по MSK на границе суток (23:30 UTC = следующий день MSK); пустой
  отбор → skip; отмена брошенных загрузок только по своему имени.

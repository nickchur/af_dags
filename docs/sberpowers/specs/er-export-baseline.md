# Baseline-спека: er-export

- Дата: 2026-10-04
- Статус: реализована
- Источник: openspec/specs/er-export/spec.md, перевод 2026-10-04

## Назначение

Фреймворк выгрузок ЕР: данные из ClickHouse уезжают в S3 архивами, а ТФС узнаёт о них уведомлением через Kafka. Всё поведение задаётся строками управляющей таблицы `export.er_wf_meta` — новая поставка добавляется записью, а не кодом. Один DAG соответствует одному пакету, то есть одной группе поставок и одному внешнему тикету.

## Требования

- **REQ-er-export-01** — **Пакет задаётся парой replica и dag_group.** Система считает пакетом пару колонок `replica` и `dag_group` и создаёт на неё один DAG с идентификатором `export_er__<replica>__<dag_group>`. Пустая группа приводится к `0`: имена файлов строятся по фиксированному числу разделителей `__`, и пакет без группы разбирался бы принимающей стороной иначе.
- **REQ-er-export-02** — **Строка группы отличается пустым extract_name.** Строка управляющей таблицы с пустым `extract_name` описывает группу целиком: её расписание, общие параметры и значения, наследуемые поставками. Строка с заполненным `extract_name` описывает одну поставку.
- **REQ-er-export-03** — **Части ключа не содержат двойного подчёркивания.** Значения `replica`, `dag_group`, `schema_name` и `extract_name` проверяются на маску `[A-Za-z0-9_-]` и не содержат `__`. Проверка происходит при синхронизации, а не при выгрузке.
- **REQ-er-export-04** — **Признаки активности и паузы разведены.** `is_active = 0` у строки-группы означает, что DAG не создаётся вовсе; `is_paused = 1` означает, что DAG создаётся, но выключен. У поставки: неактивная не попадает в пакет, приостановленная попадает, но её задачи пропускаются.
- **REQ-er-export-05** — **Имена файлов пакета.** Архив пакета называется `{replica}__{ts}__{dag_group}__{table}__{часть}_{всего}_{строк}.zip`, тикет — `{replica}__{ts}.tkt`, файлы данных и `.meta` внутри архива — `{schema}__{table}__{ts}__…`. Имена приводятся к нижнему регистру.
- **REQ-er-export-06** — **Метаданные синхронизируются в Variable, ошибки видны сразу.** DAG настройки (`export_er_setup`) читает `export.er_wf_meta`, проверяет запись на живом ClickHouse (запрос и `.meta`) и складывает результат в Airflow Variable `datalab_er_wfs` под ключом-идентификатором DAG'а. При ошибках в метаданных таск падает, а не сохраняет частичный результат.
- **REQ-er-export-07** — **Общие настройки живут в Variable.** Настройки, общие для всех пакетов (подключения, бакет, карта маршрутов ТФС, лимиты, значения параметров по умолчанию), читаются из Variable `datalab_er_config` с падением на значения по умолчанию в коде. Правка выполняется через DAG настройки, а не правкой модуля.
- **REQ-er-export-08** — **Форма настройки открывается с видимыми полями.** Поля формы запуска DAG настройки, которыми пользуются в каждом ране (выбор записи, патч, флаги), видны сразу при открытии формы. В свёрнутую группу (`Param(section=…)`) убираются только редко используемые общие настройки, а название группы обходится без символов, особых для CSS-селектора (точка, `#`, `:`, `[`, `]`, `,`).
- **REQ-er-export-09** — **Лимит строк зависит от контура.** Число выгружаемых строк ограничивается по значению `ENV_STAND` (при её отсутствии — `ENVIRONMENT`): на `PROM` ограничения нет, на прочих известных контурах действует лимит из настроек. Неизвестный контур выгружается без ограничения.
- **REQ-er-export-10** — **Режимы выгрузки.** Система поддерживает три режима: инкрементальный (`delta`) по окну из состояния, скользящее окно (`recent`) без сохранения состояния и ручную выгрузку за период. Ручная выгрузка за период не двигает состояние дельты, если в форме запуска не отмечен `shift_state` «Сдвинуть состояние дельты». С отметкой период записывается в историю как окно поставки по дельте, и следующая дельта продолжает от `date_to`. Сдвиг выполняется только вперёд и не дальше текущего времени: `date_to` не позже достигнутого состояния, `date_to` позже текущего времени (UTC) или отметка без периода останавливает ран ошибкой в `init`.
- **REQ-er-export-11** — **Результат пакета пишется одной вставкой.** Таск сохранения статуса записывает по строке на каждую отработавшую таблицу пакета одной вставкой и запускается и после пропуска ожидания (`trigger_rule` допускает пропущенные предшественники). Время подтверждения записывается фактическим значением из ожидания квитанции, а при отсутствии ожидания — пустым.
- **REQ-er-export-12** — **Пауза отправки останавливает и ожидание квитанции.** Перед ожиданием подтверждения и повторно при истечении таймаута ожидания система проверяет правила паузы тракта по ключу пакета (реплика с группой, маршрут, метка времени). При действующей паузе ожидание завершается пропуском с заметкой, а не падением.
- **REQ-er-export-13** — **Ключ пакета в очереди совпадает с ключом паузы.** Строка, по которой ищется правило паузы в выгрузке, совпадает с той, что кладётся в очередь отправки: имя пакета (реплика с группой), а не голая реплика.
- **REQ-er-export-14** — **Состояние дельты живёт в собственной таблице ЕР.** Состояние дельты хранится в `export.er_extract_history`, где выгрузка опознаётся колонками `replica`, `schema_name`, `extract_name`. Строка несёт и происхождение записи: `dag_id`, `run_id`, `dag_group`, `package_ts` и режим выгрузки. Общая с xStream `export.extract_history` не изменяется и не пополняется записями ЕР.
- **REQ-er-export-15** — **Окно дельты считается по настройке поставки.** Окно следующей выгрузки вычисляется кодом от достигнутого состояния: нижняя граница отодвигается назад на `overlap` секунд, верхняя — до текущего времени, а при `increment` > 0 не дальше чем на `increment` минут. По умолчанию `increment = 0`: отставшая поставка догоняет текущее время одним раном. `increment` и `overlap` берутся из настройки поставки, а не из ранее записанной строки истории.
- **REQ-er-export-16** — **Поставка активна только в одной группе реплики.** Ключ состояния дельты группы не содержит, поэтому синхронизация отвергает настройку, в которой одна тройка `(replica, schema_name, extract_name)` активна в двух группах одной реплики, и называет эти группы в причине отказа. Приостановленная и выключенная поставки состояние не двигают, поэтому такую пару синхронизация пропускает с предупреждением — иначе поставку нельзя было бы перенести из группы в группу.
- **REQ-er-export-17** — **Начальная точка новой поставки.** При первом запуске поставки по дельте (истории нет) начальной точкой является `lower_bound`, а при пустом `lower_bound` — `min(time_field)` по запросу поставки без окна минус секунда; в минимуме участвуют только значения с 2000 года, `time_field` типа `Date` даёт полночь этой даты. Пустой источник пропускает таблицу без записи состояния, а источник со строками, но без значений с 2000 года, останавливает первый ран ошибкой с просьбой задать `lower_bound`. Поставку с историей, чьё состояние раньше 2000 года, синхронизация `export_er_setup` называет в предупреждениях с лечением — ран с периодом и `shift_state`.
- **REQ-er-export-18** — **Имена колонок файла данных совпадают с .meta.** Колонка, имя которой есть в списке зарезервированных слов Hive, получает в `.meta` суффикс `_`. Запрос данных даёт этой колонке то же имя с суффиксом, чтобы заголовок TSV и ключи JSON совпадали с `.meta`. Выражение без выводимого имени остаётся как есть. Список задаётся в общих настройках (`datalab_er_config`, ключ `HIVE_RESERVED`) и по умолчанию пуст: слово добавляется осознанно. Форма `export_er_setup` отвергает список с не-идентификатором.

## Ограничения и контракты

- Идентификатор DAG'а пакета: `export_er__<replica>__<dag_group>` (REQ-er-export-01).
- Пустая `dag_group` приводится к `0` — значение по умолчанию (REQ-er-export-01).
- Маска частей ключа (`replica`, `dag_group`, `schema_name`, `extract_name`): `[A-Za-z0-9_-]` без двойного подчёркивания `__` (REQ-er-export-03).
- Имя архива пакета: `{replica}__{ts}__{dag_group}__{table}__{часть}_{всего}_{строк}.zip` (REQ-er-export-05).
- Имя тикета: `{replica}__{ts}.tkt` (REQ-er-export-05).
- Имена файлов данных и `.meta` внутри архива: `{schema}__{table}__{ts}__…` (REQ-er-export-05).
- Имена файлов пакета приводятся к нижнему регистру; метку времени выдаёт таск в пуле с одним слотом на реплику (REQ-er-export-05).
- Имя DAG настройки: `export_er_setup` (REQ-er-export-06).
- Имя управляющей таблицы: `export.er_wf_meta` (REQ-er-export-06).
- Имя переменной с метаданными пакетов: `datalab_er_wfs` (REQ-er-export-06).
- Имя переменной с общими настройками: `datalab_er_config` (REQ-er-export-07).
- Запрещённые символы в названии `Param(section=…)`: точка, `#`, `:`, `[`, `]`, `,` (REQ-er-export-08).
- Имя переменной контура: `ENV_STAND`, при её отсутствии `ENVIRONMENT` (REQ-er-export-09).
- Карта контуров лимита: `PROM` — без лимита, прочие известные — лимит из настроек, неизвестный — без лимита (REQ-er-export-09).
- Режимы выгрузки: `delta`, `recent`, ручная выгрузка с периодом (REQ-er-export-10).
- Параметры ручного режима `date_from`/`date_to`/`shift_state`, отказ в `init`, если `date_to` не позже достигнутого состояния, позже текущего времени (UTC) или отметка без периода (REQ-er-export-10).
- `trigger_rule` сохранения статуса допускает пропущенных предшественников (REQ-er-export-11).
- Ключ правила паузы: реплика с группой, маршрут, метка времени; в очередь кладётся тот же ключ — имя пакета, а не голая реплика (REQ-er-export-12, REQ-er-export-13).
- Имя таблицы истории ЕР: `export.er_extract_history` (REQ-er-export-14).
- Ключ выгрузки в истории: `replica`, `schema_name`, `extract_name` (REQ-er-export-14).
- Поля происхождения записи в истории: `dag_id`, `run_id`, `dag_group`, `package_ts`, режим выгрузки (REQ-er-export-14).
- Таблица истории xStream `export.extract_history` не используется для записей ЕР (REQ-er-export-14).
- Единицы окна: `overlap` — секунды, `increment` — минуты; источник — настройка поставки, не строка истории (REQ-er-export-15).
- Значение `increment` по умолчанию: `0` (REQ-er-export-15).
- Начальная точка: `lower_bound`, иначе `min(time_field)` по значениям с `2000-01-01` минус секунда; тот же порог у предупреждения о застрявшем состоянии; сбой чтения состояний в синхронизации — предупреждение, а не ошибка (REQ-er-export-17).
- Ключ списка зарезервированных слов Hive в настройках: `HIVE_RESERVED` (REQ-er-export-18).
- Суффикс зарезервированных слов Hive: `_` (REQ-er-export-18).
- Значение списка `HIVE_RESERVED` по умолчанию: пусто (REQ-er-export-18).

## Non-goals

В исходной спецификации границы не записаны; дополняется при первой дельте.

## Критерии приёмки

| REQ-ID | Сценарий проверки |
|---|---|
| REQ-er-export-01 | Группа не заполнена: дано в строке `er_wf_meta` колонка `dag_group` пуста → действие синхронизация → результат синхронизация подставляет `0`, и DAG называется `export_er__<replica>__0` |
| REQ-er-export-01 | Одна таблица в разных группах: дано одна и та же таблица входит в два пакета одной реплики → действие создание DAG'ов → результат это два разных DAG'а, и их архивы не совпадают именами |
| REQ-er-export-02 | Значение не задано у поставки: дано у поставки не заполнено поле, заполненное в строке-группе → действие чтение настроек → результат поставка получает значение строки-группы |
| REQ-er-export-03 | Имя с двойным подчёркиванием: дано в `er_wf_meta` появляется поставка с `extract_name = 'my__table'` → действие проверка при синхронизации → результат синхронизация сообщает об ошибке и не выпускает такую поставку в работу: иначе имя архива распалось бы на лишние части и принимающая сторона разобрала бы его неверно |
| REQ-er-export-04 | Группа выключена: дано у строки-группы `is_active = 0` → действие создание DAG'а → результат DAG пакета в Airflow отсутствует |
| REQ-er-export-04 | Группа заведена заранее: дано у строки-группы `is_active = 1` и `is_paused = 1` → действие создание DAG'а → результат DAG создаётся выключенным и ждёт, пока его включат руками |
| REQ-er-export-04 | Поставка приостановлена: дано у поставки `is_paused = 1` → действие создание DAG'а → результат её TaskGroup в пакете есть, но выгрузка пропускается, а флаг включения снят по умолчанию |
| REQ-er-export-05 | Метка времени разводит пакеты одной реплики: дано две группы одной реплики выгружаются рядом по времени → действие генерация метки времени → результат метку выдаёт отдельный таск в пуле с единственным слотом на реплику, поэтому секунды у пакетов разные и имена не сталкиваются |
| REQ-er-export-06 | Поле, которого нет в источнике: дано в поставке перечислено поле, отсутствующее в исходной таблице → действие синхронизация метаданных → результат проверка падает с перечислением расхождений, Variable остаётся прежней |
| REQ-er-export-06 | Пакет с непроходимыми метаданными: дано запись не проходит проверки, но уже была выпущена → действие синхронизация метаданных → результат вместо рабочего DAG'а создаётся DAG-заглушка с текстом ошибок, выключенный при создании |
| REQ-er-export-07 | Переопределение неизвестного ключа: дано в Variable оказался ключ, которого нет среди переопределяемых → действие чтение настроек → результат он игнорируется с предупреждением в лог, а остальные настройки применяются |
| REQ-er-export-08 | Открытие формы запуска: дано — → действие пользователь открывает форму запуска DAG настройки → результат выпадающий список записей, поле патча и флаги видны без раскрытия групп, а общие настройки лежат ниже в свёрнутой группе |
| REQ-er-export-08 | Название группы с точкой: дано название группы полей содержит точку → действие открытие формы запуска → результат это ошибка: Airflow строит из названия id гармошки без экранирования, и Bootstrap не находит панель по селектору — группа не раскрывается вовсе |
| REQ-er-export-09 | Выгрузка на тестовом контуре: дано `ENV_STAND = DEV` → действие выгрузка → результат запрос оборачивается в `LIMIT` со значением из настроек |
| REQ-er-export-10 | Разовая выгрузка за прошлый месяц: дано пакет запущен руками с заданными `date_from` / `date_to` без `shift_state` → действие выгрузка → результат данные выгружаются за указанный период, а окно следующей штатной дельты остаётся прежним |
| REQ-er-export-10 | Застрявшая поставка переводится вперёд: дано состояние дельты поставки стоит в 1970 году, и пакет запущен с `date_from`, `date_to` = текущее время и отмеченным `shift_state` → действие выгрузка → результат период выгружается и записывается в историю, а следующий ран считает окно от `date_to` |
| REQ-er-export-10 | Сдвиг в будущее: дано отмечен `shift_state`, а `date_to` позже текущего времени → действие выгрузка → результат `init` падает с объяснением, история не меняется |
| REQ-er-export-10 | Сдвиг назад: дано отмечен `shift_state`, а `date_to` не позже достигнутого состояния → действие выгрузка → результат `init` падает с объяснением, история не меняется |
| REQ-er-export-11 | Ожидание пропущено: дано пакет выгружен с `auto_confirm = 1` → действие сохранение статуса → результат статус сохраняется, а поле подтверждения остаётся пустым — это отличимо от случая «ждали и дождались» |
| REQ-er-export-12 | Паузу поставили до запуска пакета: дано отправка на паузе → действие пакет дошёл до ожидания квитанции → результат ожидание пропускается сразу, слот пула не занимается на час, состояние дельты двигается, и пакет уедет после снятия паузы |
| REQ-er-export-12 | Паузу поставили и сняли внутри часа ожидания: дано таск ждёт квитанцию → действие пауза появилась и исчезла → результат ожидание идёт своим чередом: проверка делается на входе и по таймауту, а не внутри цикла |
| REQ-er-export-13 | Пауза на пакетном DAG'е: дано правило паузы поставлено на конкретный пакет → действие отправка пакета и ожидание квитанций → результат его видят и отправитель, и ожидание квитанций; иначе пакет досидел бы до таймаута без объяснения причины |

# Baseline-спека: gp-exchange

- Дата: 2026-10-04
- Статус: реализована
- Источник: openspec/specs/gp-exchange/spec.md, перевод 2026-10-04

## Назначение

Приём универсального обмена из ПКАП: файлы с JSON-пакетами приезжают через ТФС в S3, загружаются в ClickHouse, разбираются по потокам и раскладываются в целевые таблицы. Пакет собирает Greenplum (`pr_exchange`), поэтому формат файла и содержимое контрольных записей — общий договор двух сторон: менять его можно только согласованно.

## Требования

- **REQ-gp-exchange-01** — **Появление файла запускает загрузку.** Отдельный DAG-сенсор следит за появлением файлов по маске в бакете ТФС и публикует Dataset, запускающий загрузку; сенсор работает в режиме `reschedule` и не падает при отсутствии файлов.
- **REQ-gp-exchange-02** — **Формат файла задан приёмной стороной.** Файл читается как таблица с разделителем-табуляцией и строкой заголовка, без обрамления полей кавычками. Колонки соответствуют результату сборщика пакета: идентификатор пакета, имя потока, ключ инкремента, данные строки в JSON.
- **REQ-gp-exchange-03** — **Загрузка идёт по файлу на задачу.** Каждый найденный файл загружается своей задачей, чтобы сбой на одном файле не отменял остальные и был виден по имени.
- **REQ-gp-exchange-04** — **Объём загруженного сверяется с контрольными записями пакета.** Фактически загруженное сверяется с контрольными записями пакета (`OUT` по каждому потоку, `SUM` по всему пакету), и при расхождении задача падает; набор опций сверки передаётся явно.
- **REQ-gp-exchange-05** — **Перенос в основную таблицу дедуплицирует и хэширует.** Данные переносятся из промежуточной таблицы в основную с отметкой времени запуска, хэшем содержимого и без дублей, при этом основная таблица разложена по потокам.
- **REQ-gp-exchange-06** — **Промежуточная таблица и бакет чистятся после переноса.** После переноса перенесённые пакеты удаляются из промежуточной таблицы, а обработанные файлы — из бакета S3.
- **REQ-gp-exchange-07** — **Ветвление по потокам.** Система определяет приехавшие потоки и запускает только объявленные в DAG задачи обработки, отправляя потоки без задач в разведку (`process__other`), а служебные записи журнала не обрабатываются как поток.
- **REQ-gp-exchange-08** — **Завершение публикует событие.** По окончании обработки публикуется Dataset для зависимых DAG'ов, даже если обрабатывать было нечего.
- **REQ-gp-exchange-09** — **Обработка потока грузит только новое.** Задача обработки разбирает JSON в колонки целевой таблицы и вставляет только строки с идентификатором пакета выше уже загруженного, применяя перед вставкой заданную стратегию очистки.
- **REQ-gp-exchange-10** — **Очистка и удаление источника адресуются именем потока.** Стратегии очистки и удаление обработанных данных из основной таблицы адресуются именем потока (`_gp_name`), а не именем целевой таблицы.
- **REQ-gp-exchange-11** — **Целевые таблицы создаются человеком.** Целевая таблица не создаётся автоматически; при её отсутствии задача падает с приложенным DDL-запросом `CREATE TABLE`, собранным из описания полей потока.
- **REQ-gp-exchange-12** — **Типы полей определяются по данным.** Если состав полей не задан явно, имена определяются из ключей JSON, типы — из фактических значений (при конфликте выбирается строка), а составные значения приводятся к строке.
- **REQ-gp-exchange-13** — **Имена и типы из данных проверяются перед подстановкой в SQL.** Имя поля проверяется как идентификатор, а тип — как имя типа; негодное поле роняет задачу загрузки в целевую таблицу или пропускается с предупреждением при разведке.
- **REQ-gp-exchange-14** — **Каждая загрузка отмечается в журнале.** После обработки потока в журнал загрузки записывается строка с именем потока, идентификатором пакета и числом строк, которая служит отсечкой для следующего ветвления.
- **REQ-gp-exchange-15** — **Конфигурация тракта в одном месте.** Сценарий ТФС, бакет, префикс, топик и подключения объявлены в общем модуле каталога и используются обоими DAG'ами без дублирования.

## Ограничения и контракты

- Режим работы DAG-сенсора: `reschedule` (REQ-gp-exchange-01).
- Формат файла: разделитель-табуляция, со строкой заголовка, без обрамления полей кавычками (REQ-gp-exchange-02).
- Колонки файла: идентификатор пакета, имя потока, ключ инкремента, данные строки в JSON (REQ-gp-exchange-02).
- Контрольные записи пакета: `OUT` по каждому потоку, `SUM` по всему пакету (REQ-gp-exchange-04).
- Разведка незнакомых потоков: задача `process__other` (REQ-gp-exchange-07).
- Стратегии очистки перед вставкой: удаление партиций, удаление строк, очистка целиком, слияние (REQ-gp-exchange-09).
- Адресация очистки и удаления по имени потока: поле `_gp_name`, а не имя целевой таблицы (например, `_exchange_log` против `gp__exchange_log`) (REQ-gp-exchange-10).
- Приведение типов: составные значения (объекты и массивы) приводятся к строке; при конфликте типов поля выбирается строка (REQ-gp-exchange-12).

## Критерии приёмки

| REQ-ID | Сценарий проверки |
|---|---|
| REQ-gp-exchange-01 | За окно проверки файлов не появилось: дано файлов, подходящих под маску, нет → действие сенсор отработал отведённое время → результат он завершается пропуском, а не ошибкой: отсутствие файлов — обычное состояние |
| REQ-gp-exchange-01 | Файл появился: дано — → действие в бакете возник файл, подходящий под маску → результат публикуется Dataset, и DAG загрузки запускается сам |
| REQ-gp-exchange-02 | Поле содержит кавычки: дано JSON-данные строки содержат двойные кавычки (а они там всегда) → действие чтение файла → результат они попадают в ClickHouse как часть значения, потому что выгрузка не оборачивает поля в кавычки |
| REQ-gp-exchange-03 | Один файл повреждён: дано один из нескольких файлов не читается → действие загрузка файлов → результат остальные загружаются, а упавший виден отдельной задачей |
| REQ-gp-exchange-04 | Строк доехало меньше заявленного: дано в контрольной записи потока указано больше строк, чем загрузилось → действие сверка загруженного → результат задача сверки падает с перечислением расхождений |
| REQ-gp-exchange-04 | Сверка текущего запуска: дано — → действие сверка запущена с опцией «только текущий запуск» → результат она смотрит записи этого запуска, а не всю историю: иначе давнее расхождение красит каждый прогон, а свежее теряется под старым совпадением |
| REQ-gp-exchange-05 | Файл загрузили дважды: дано — → действие тот же пакет пришёл повторно → результат в основной таблице не появляется дублей: строки совпадают по хэшу содержимого |
| REQ-gp-exchange-06 | Пакет перенесён: дано данные пакета оказались в основной таблице → действие очистка промежуточных данных → результат его партиция в промежуточной таблице удаляется, а файл — из бакета |
| REQ-gp-exchange-07 | Приехал незнакомый поток: дано в пакете есть `_gp_name`, которому не соответствует ни одна задача → действие ветвление по потокам → результат запускается разведка: она показывает набор полей и образец строк, чтобы можно было завести целевую таблицу |
| REQ-gp-exchange-07 | Поток ещё ни разу не грузился: дано по потоку нет ни одной записи в журнале загрузки → действие ветвление по потокам → результат он всё равно попадает в обработку — первый пакет не должен требовать ручной затравки журнала |
| REQ-gp-exchange-08 | В пакете не оказалось ни одного известного потока: дано ветвление не выбрало ни одной задачи обработки → действие завершение DAG'а → результат DAG всё равно завершается публикацией события: молчаливый зелёный прогон неотличим от «данные приехали и разложены» |
| REQ-gp-exchange-09 | Повторный запуск на тех же данных: дано — → действие задача обработки запущена ещё раз без нового пакета → результат новых строк в целевой таблице не появляется |
| REQ-gp-exchange-10 | Удаление источника после переноса: дано поток обработан и настроено удаление источника → действие очистка и удаление → результат удаляется партиция этого потока; операция, адресованная именем таблицы, не нашла бы партицию и завершилась бы молча |
| REQ-gp-exchange-11 | Новый поток заводят в работу: дано целевой таблицы ещё нет → действие задача загрузки в целевую таблицу → результат в тексте ошибки лежит DDL, который остаётся проверить, поправить типы и выполнить |
| REQ-gp-exchange-12 | Число то целое, то дробное: дано в одной строке поле пришло целым, а в другой дробным → действие определение типа поля → результат поле объявляется строкой, а не склейкой двух типов: такого типа не существует, и разбор падал бы на первом же значении |
| REQ-gp-exchange-13 | Ключ JSON содержит фрагмент запроса: дано во входных данных встречается ключ вида `x') as y, (select …` → действие подстановка имени поля в SQL → результат он не попадает в SQL: задача останавливается либо поле пропускается, в зависимости от того, грузим мы поток или разведываем |
| REQ-gp-exchange-14 | Следующий пакет того же потока: дано — → действие приходит пакет с идентификатором выше записанного в журнале → результат поток попадает в обработку; пакет с прежним идентификатором — нет |
| REQ-gp-exchange-15 | Переезд маршрута: дано — → действие меняется префикс или бакет тракта → результат правка делается в одном месте, и сенсор с загрузчиком остаются согласованными |

# Baseline-спека: plugins

- Дата: 2026-10-04
- Статус: реализована
- Источник: openspec/specs/plugins/spec.md, перевод 2026-10-04

## Назначение

Общие модули, которыми пользуются все DAG'и репозитория: конфигурация, обёртки над базами, работа с S3, утилиты Airflow (заметки, пулы, параметры) и хранилище тракта ТФС. Каталог задаёт контракты, на которые опираются остальные шесть проектов, поэтому его правки задевают всех — совместимость важнее удобства отдельного вызывающего.

## Требования

- **REQ-plugins-01** — **Потоковые операции с S3 защищены лимитом памяти.** Потоковые чтение и распаковка объектов S3 работают без записи на диск и прерываются, когда буфер в памяти превышает жёсткий предел; при приближении к пределу пишется предупреждение. Предел проверяется по мере набора данных, как при чтении порциями, так и при чтении потока целиком: проверка после того, как поток собран в памяти, не допускается.
- **REQ-plugins-02** — **Общие утилиты Airflow.** Модуль `utils` предоставляет единые способы для работы с заметками, колбэками, пулами, параметрами запуска, паузой DAG'а, разбором интервалов и определением контура. Дописывание заметки переживает параллельную запись за счёт перечитывания под блокировкой, а невозможность заблокировать строку не роняет задачу.
- **REQ-plugins-03** — **Контур тракта ТФС определяется наличием ENVIRONMENT.** Выбор контура в `tfs_utils` (альфа или сигма), от которого зависит топик отправки, опирается исключительно на наличие переменной окружения `ENVIRONMENT`, а переменные `ENV_SPACE` и `ENV_STAND` для этого не используются.
- **REQ-plugins-04** — **Конфигурация тракта ТФС существует в одном экземпляре.** Настройки, имена таблиц и функции тракта ТФС живут в `plugins/tfs_utils.py` и используются как отправителем, так и выгрузками, без копирования в каталоги-потребители.
- **REQ-plugins-05** — **Импорт общих модулей не ходит в сеть и не требует Airflow Variables.** Модули `plugins` выполняют чтение конфигурации, списка бакетов и сетевые обращения только при первом фактическом вызове, поэтому парсинг DAG-файла с недоступной базой, отсутствующей Variable или неработающим S3 завершается успешно.
- **REQ-plugins-06** — **Одна проверка доступности подключения на все даги.** Функция `chk_conn` в `plugins/utils.py` проверяет подключение различных типов по `conn_id` без конфигурации CTL: успех оставляет заметку, отсутствие провайдера пропускается, а недоступность роняет задачу с ошибкой.

## Ограничения и контракты

- Жёсткий предел буфера в памяти: 512 МБ (REQ-plugins-01).
- Предупреждение о размере буфера памяти пишется на 100 МБ (REQ-plugins-01).
- Исключение при превышении лимита памяти: `MemoryError` (REQ-plugins-01).
- Утилиты Airflow в `utils`: `add_note`, `on_callback`, `pool_slots`, `ensure_pool`, `store_params`, `saved_params`, `update_dag_pause`, `str2timedelta`, `env_stand` (REQ-plugins-02).
- Переменные определения контура Airflow: `ENV_STAND`, при отсутствии — `ENVIRONMENT` (REQ-plugins-02).
- Приведение имени контура к верхнему регистру, пустое значение при отсутствии обеих переменных (REQ-plugins-02).
- Определение контура ТФС: наличие `ENVIRONMENT` — альфа, отсутствие — сигма (REQ-plugins-03).
- Значение переменной `ENV_SPACE` на альфа-стенде намеренно выставлено в `sigma` и не используется для определения контура (REQ-plugins-03).
- Топик отправки ТФС на альфе: `TFS.PKAPHR.IN` (REQ-plugins-03).
- Топик отправки ТФС на сигме: `TFS.HRPLT.IN` (REQ-plugins-03).
- Расположение конфигурации ТФС: `plugins/tfs_utils.py` (REQ-plugins-04).
- Типы подключений `chk_conn`: `Postgres`, `S3`, `KerberosHttp` (REQ-plugins-06).
- Исключение при недоступности подключения: `AirflowFailException` (REQ-plugins-06).

## Критерии приёмки

| REQ-ID | Сценарий проверки |
|---|---|
| REQ-plugins-01 | Аномально большой файл в архиве: дано — → действие распаковка одного файла из ZIP уводит буфер за 512 МБ → результат операция прерывается `MemoryError`, воркер не уходит в OOM |
| REQ-plugins-01 | Поток читают целиком: дано содержимое потока больше предела → действие у потока запрашивают всё содержимое сразу → результат чтение прерывается на пороге, а не после того, как всё уже в памяти |
| REQ-plugins-02 | Заметка уровня DAG: дано — → действие таск зовёт `add_note(data, context, level='DAG')` → результат заметка появляется у DAG-run, а не только у таска, и видна в UI без чтения логов |
| REQ-plugins-02 | Несколько задач пишут в заметку одного рана: дано — → действие параллельные задачи одного прогона дописывают свои строки в заметку DAG-run → результат в заметке остаются строки всех, а не только последнего записавшего |
| REQ-plugins-02 | Сохранение параметров запуска: дано — → действие пользователь запустил DAG с флагом сохранения параметров → результат параметры кладутся в Variable и подставляются в следующий запуск, а результат операции возвращается парой `(status, message)` |
| REQ-plugins-02 | Контур задан запасным именем переменной: дано выставлена только `ENVIRONMENT`, а `ENV_STAND` нет → действие определение контура → результат контур определяется по `ENVIRONMENT`, и поведение совпадает с тем, как если бы была выставлена `ENV_STAND` |
| REQ-plugins-03 | Альфа опознаётся по заданной переменной: дано в окружении задана `ENVIRONMENT`, а `ENV_SPACE` равен `sigma` → действие определение контура → результат контур считается альфой и отправка идёт в `TFS.PKAPHR.IN`, то есть значение `ENV_SPACE` на решение не влияет |
| REQ-plugins-03 | Сигма опознаётся по отсутствию переменной: дано `ENVIRONMENT` в окружении нет → действие определение контура → результат контур считается сигмой и отправка идёт в `TFS.HRPLT.IN` |
| REQ-plugins-03 | Вывод о контуре виден в дампе настроек: дано — → действие оператор смотрит `tfs_utils.get_config()` → результат рядом стоят выведенный контур и сама `ENVIRONMENT`, по которой вывод сделан, и расхождение с переменной окружения `ENV_SPACE` не сбивает с толку |
| REQ-plugins-04 | Приёмник и ожидание разошлись бы в путях: дано появляется соблазн продублировать путь к квитанции рядом с DAG'ом-потребителем → действие размещение настроек → результат этого не делается: разъехавшиеся копии подвешивают пакет до таймаута, а причина не видна ни в одном логе |
| REQ-plugins-05 | S3 недоступен при разборе DAG'а: дано S3 не отвечает → действие Airflow разбирает DAG, импортирующий модули `plugins` → результат импорт проходит; S3 понадобится только первому вызову, который в него пишет или читает |
| REQ-plugins-06 | Проверка на сигме: дано на контуре без CTL-кода требуется проверить подключение S3 → действие `tools_test_connections` проверяет S3-подключение на контуре без CTL-кода → результат проверка идёт через `chk_conn` из общих модулей, без импорта `ctl_worker` |
| REQ-plugins-06 | Сторож подключений CTL: дано — → действие `chk_any_conn` проверяет подключение из конфига CTL → результат проверку выполняет та же `chk_conn`, а размер пула задаёт обёртка CTL |

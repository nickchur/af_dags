# Baseline-спека: s3-tools

- Дата: 2026-10-04
- Статус: реализована
- Источник: openspec/specs/s3-tools/spec.md, перевод 2026-10-04

## Назначение

Служебные DAG'и для администрирования и отладки: просмотр бакетов и ключей S3, чтение файлов, копирование и перемещение объектов, управление TTL, загрузка контента, генерация тестовых пакетов формата ЕР/ТФС. Все они запускаются человеком по необходимости и действуют в чужих бакетах, поэтому цена ошибки здесь — не «неверный отчёт», а испорченные или удалённые данные.

## Требования

- **REQ-s3-tools-01** — **Только ручной запуск.** DAG'и каталога создаются без расписания и выключенными при первом появлении (`is_paused_upon_creation`). Инструмент, работающий с хранилищем, дополнительно ограничивается одним активным запуском. Служебная операция не выполняется сама по себе; на демонстрационные шаблоны без побочных эффектов ограничение параллельных запусков не распространяется.
- **REQ-s3-tools-02** — **Инструменты записи не существуют на PROM.** DAG, который создаёт или подменяет содержимое в S3 из введённых руками данных (загрузка контента, генератор тестовых пакетов), не регистрируется на боевом контуре: при `ENV_STAND = prom` файл завершается без создания DAG'а, оставив запись в логе.
- **REQ-s3-tools-03** — **Всё, что определяет операцию, задаётся формой запуска.** Инструмент принимает подключение, бакет, путь, маску, приёмник, срок хранения и режимы параметрами запуска. Параметры ограничиваются там, где границы известны: список подключений — перечислением доступных, числовые — минимумом и максимумом.
- **REQ-s3-tools-04** — **Предусловия проверяются до первого изменения.** Инструмент проверяет существование подключения и доступность бакета до начала операции и останавливается, не оставив частичного результата, если проверка не прошла. Останов видим в UI: пропуск для незаполненной формы, падение для заданных, но недостижимых объектов.
- **REQ-s3-tools-05** — **Пути задаются единым форматом с маской.** Инструменты, работающие с набором объектов, принимают путь в форме `conn_id://bucket/prefix/mask` и разбирают его на статический префикс и маску по первому спецсимволу (`*` или `?`). Отсутствие маски означает «всё под префиксом».
- **REQ-s3-tools-06** — **Объём выборки ограничен.** Инструменты просмотра и массовых операций ограничивают число обрабатываемых объектов, размер страницы листинга и число читаемых строк, с значениями по умолчанию, безопасными для большого бакета.
- **REQ-s3-tools-07** — **Перезапись только по явному флагу.** Загрузка и копирование не перезаписывают существующий объект по умолчанию: перезапись включается отдельным флагом запуска.
- **REQ-s3-tools-08** — **Копирование, перемещение и удаление разведены флагами.** Инструмент переноса различает три режима: копирование (источник остаётся), перемещение (источник удаляется после успешной записи) и удаление без копирования. Удаление источника происходит только после того, как приёмник записан.
- **REQ-s3-tools-09** — **Сжатие и распаковка по требованию.** Инструменты переноса и загрузки поддерживают сжатие результата (`gz`, `zip`, `tar.gz`) и распаковку ZIP на лету, без записи на диск. Имя архива и имя файла внутри него выводятся из целевого ключа. Повторное сжатие уже сжатого файла не применяется, если расширение источника совпадает с запрошенным сжатием.
- **REQ-s3-tools-10** — **Ошибка на одном объекте не отменяет остальные.** Массовые операции выполняются по объекту на задачу, чтобы падение на одном файле не отменяло обработку остальных, и остаются видимыми: неуспешный объект даёт красную задачу со своим именем в индексе.
- **REQ-s3-tools-11** — **Результат виден без чтения логов.** Инструмент, который что-то нашёл, скопировал, удалил или изменил, складывает итог работы (ключи, размеры, прежние и новые правила TTL, сводку по бакетам) в заметку DAG-run или задачи. Требование не распространяется на шаблоны и демонстрационные DAG'и, у которых результата нет.
- **REQ-s3-tools-12** — **Обзор хранилища не падает из-за одного подключения.** Инструмент обзора всех бакетов обходит все подключения типа S3 и продолжает работу, если по какому-то подключению или бакету не удалось получить список, размер или правила TTL: неудача попадает в отчёт как свойство этой строки.
- **REQ-s3-tools-13** — **Генератор тестовых пакетов повторяет боевой формат.** Инструмент подготовки тестовых пакетов собирает ZIP по тем же правилам именования, что и настоящая выгрузка ЕР: архив `{реплика}__{ts}__{группа}__{таблица}__{часть}_{всего}_{строк}.csv.zip`, внутри — файл данных, `.meta` и `.tkt`, а поверх пакета — итоговый `.tkt` со списком архивов. Метки времени внутри пакета идут по возрастанию, чтобы порядок был воспроизводим.

## Ограничения и контракты

- DAG'и создаются без расписания (REQ-s3-tools-01).
- DAG'и выключены при первом появлении (`is_paused_upon_creation`) (REQ-s3-tools-01).
- Ограничение параллельных запусков (один активный) для инструментов с хранилищем (REQ-s3-tools-01).
- Переменная окружения `ENV_STAND` со значением `prom` (REQ-s3-tools-02).
- Формат пути `conn_id://bucket/prefix/mask` со спецсимволами `*` и `?` (REQ-s3-tools-05).
- Значения по умолчанию для числа обрабатываемых объектов, размера страницы листинга и числа читаемых строк (REQ-s3-tools-06).
- Режимы переноса: копирование, перемещение, удаление без копирования (REQ-s3-tools-08).
- Суффикс `.done` для файла-триггера завершения (REQ-s3-tools-08).
- Поддерживаемые форматы сжатия: `gz`, `zip`, `tar.gz` (REQ-s3-tools-09).
- Формат имени архива генератора тестовых пакетов: `{реплика}__{ts}__{группа}__{таблица}__{часть}_{всего}_{строк}.csv.zip` (REQ-s3-tools-13).
- Внутренние файлы пакета: файл данных, `.meta`, `.tkt` внутри и итоговый `.tkt` со списком архивов поверх пакета (REQ-s3-tools-13).

## Non-goals

## Критерии приёмки

| REQ-ID | Сценарий проверки |
|---|---|
| REQ-s3-tools-01 | Инструмент выложен на контур: дано файл разобран, и DAG появился в Airflow → действие запуск по расписанию → результат он выключен и не запускается по времени, пока его не включат и не запустят руками |
| REQ-s3-tools-01 | Повторный запуск во время работы: дано инструмент уже выполняется → действие его запускают ещё раз → результат второй запуск ждёт завершения первого, а не работает с ним параллельно по тем же ключам |
| REQ-s3-tools-02 | Каталог выложен на боевой контур: дано те же файлы попадают на контур с `ENV_STAND = prom` → действие разбор файла → результат таких DAG'ов в UI нет вовсе — не «есть, но выключен»: включить нечего |
| REQ-s3-tools-03 | Та же операция в другом бакете: дано нужно повторить действие в другом бакете или на другом подключении → действие запуск инструмента → результат достаточно другого набора параметров запуска, правка кода не требуется |
| REQ-s3-tools-03 | Выбор подключения: дано пользователь открывает форму запуска → действие просмотр поля подключения → результат в поле подключения предложены реально заведённые на контуре подключения S3 |
| REQ-s3-tools-04 | Подключение не заведено: дано в форме указан несуществующий `conn_id` → действие запуск инструмента → результат таск останавливается с внятным текстом, ни одного объекта не создано и не удалено |
| REQ-s3-tools-04 | Бакет недоступен: дано бакет не существует или к нему нет прав → действие запуск инструмента → результат операция не начинается, а причина попадает в заметку |
| REQ-s3-tools-05 | Маска в середине пути: дано задан путь вида `s3://bucket/logs/2026-*/part-?.csv` → действие листинг файлов → результат листинг идёт по префиксу `logs/`, а отбор по маске делается уже над ним |
| REQ-s3-tools-05 | По маске ничего не нашлось: дано ни один ключ не подошёл → действие обработка файлов → результат запуск завершается пропуском с указанием пути, а не падением |
| REQ-s3-tools-06 | Маска попала на бакет с миллионом объектов: дано пользователь не менял ограничения → действие листинг файлов → результат инструмент берёт первые N по заданной сортировке и на этом останавливается, не вычитывая бакет целиком |
| REQ-s3-tools-07 | Ключ уже занят: дано объект с таким ключом уже есть, а флаг перезаписи не выставлен → действие загрузка или копирование → результат операция не выполняется, прежний объект остаётся нетронутым |
| REQ-s3-tools-08 | Копирование с удалением источника: дано выставлены и копирование, и удаление → действие перенос объекта → результат объект сначала появляется в приёмнике, и только потом исчезает из источника |
| REQ-s3-tools-08 | Только удаление: дано копирование выключено, а удаление включено → действие удаление объектов → результат найденные по маске объекты удаляются, приёмник не требуется |
| REQ-s3-tools-08 | Файл-триггер завершения: дано по маске найден ключ, оканчивающийся на `.done` → действие перенос объекта → результат обрабатывается сам файл без этого суффикса, а `.done` удаляется после переноса |
| REQ-s3-tools-09 | Ключ без расширения архива: дано запрошен `zip`, а целевой ключ — `path/data.csv` → действие сжатие объекта → результат в S3 появляется `path/data.csv.zip`, а внутри него — `data.csv` |
| REQ-s3-tools-09 | Источник уже .gz: дано копируется `.gz`-объект с запрошенным сжатием `gz` → действие сжатие объекта → результат объект переносится как есть, второй слой сжатия не накладывается |
| REQ-s3-tools-10 | Один файл битый: дано распаковка одного ZIP из десяти падает → действие перенос файлов → результат остальные девять переносятся, а упавший виден отдельной задачей с именем ключа |
| REQ-s3-tools-11 | Смена правила TTL: дано инструмент поменял правила жизненного цикла бакета → действие просмотр заметки → результат в заметке видны и прежние правила, и новые — изменение проверяемо после факта |
| REQ-s3-tools-11 | Инструмент только читает и показывает: дано DAG выводит список бакетов или содержимое файла → действие просмотр заметки → результат заметка не обязательна, если вывод и так предназначен для чтения в логе |
| REQ-s3-tools-12 | Одно подключение отвалилось: дано по одному `conn_id` листинг бакетов не удался → действие обзор бакетов → результат в отчёте у него стоит ошибка, а остальные подключения посчитаны, и есть итог |
| REQ-s3-tools-13 | Тестовый пакет для приёмной стороны: дано сгенерирован пакет из трёх частей → действие чтение пакета → результат имена файлов разбираются принимающей стороной так же, как имена боевого пакета, и итоговый `.tkt` перечисляет все три архива |

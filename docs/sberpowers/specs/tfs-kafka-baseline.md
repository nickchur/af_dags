# Baseline-спека: tfs-kafka

- Дата: 2026-10-04
- Статус: реализована
- Источник: openspec/specs/tfs-kafka/spec.md, перевод 2026-10-04

## Назначение

Тракт обмена с ТФС: отправка уведомлений о готовых пакетах в Kafka с соблюдением темпа, приём обратных квитанций из общего топика и управление паузой отправки. Тракт общий — сейчас им пользуется ЕР, следующим переезжает xStream, — поэтому конфигурация и хранилище живут в `plugins/tfs_utils.py`, а не рядом с DAG'ами.

## Требования

- **REQ-tfs-kafka-01** — **Источник истины тракта один.** Состояние тракта (очередь отправки, отметки об отправке, квитанции) хранится в одном месте, в S3 и таблицах, объявленных в `tfs_utils`, дублирование путей или имён таблиц в каталогах-потребителях не допускается.
- **REQ-tfs-kafka-02** — **Квитанция разбирается по каждому файлу.** Разбор `TransferFileCephRs` возвращает по строке на каждый агрегат `File` квитанции со своим кодом статуса, а ключом хранения является пара `(rq_uid, file_name)`.
- **REQ-tfs-kafka-03** — **Приём идёт из общего топика по всем маршрутам.** Приёмник читает квитанции из перечисленных топиков, заводит по сенсору на топик и записывает, из какого топика пришло сообщение; выгрузки эти топики не читают.
- **REQ-tfs-kafka-04** — **Темп отправки ограничен лимитами маршрута.** Отправка соблюдает скользящие лимиты маршрута (по умолчанию 10 в секунду, 200 в минуту, 500 в час и 2000 в сутки) и берёт лимиты конкретного маршрута, если они заданы отдельно.
- **REQ-tfs-kafka-05** — **Пауза отправки трёх уровней.** Система поддерживает правила паузы трёх областей: пакет, реплика и маршрут; причина выбирается от частного к общему, правило со сроком перестаёт действовать само по истечении срока.
- **REQ-tfs-kafka-06** — **Придержанное не считается затором.** Строки очереди, придержанные паузой, не учитываются как признак затора отправки, проверка простоя смотрит только на свободные строки.
- **REQ-tfs-kafka-07** — **Нарастающий алерт о забытой паузе.** Система сообщает о действующей паузе на порогах, растущих степенями двойки от одного часа (1, 2, 4, 8, 16 …), без верхнего предела; сработавший порог отмечается в самом правиле, чтобы об одном пороге не сообщать дважды; возраст считается от момента постановки правила и не сбрасывается при правке причины или продлении срока.
- **REQ-tfs-kafka-08** — **Бессрочная пауза краснеет, срочная — нет.** Таск-сторож падает, когда сработавший порог относится к правилу без срока, и завершается успешно для правила со сроком, ретраев у сторожа нет.
- **REQ-tfs-kafka-09** — **Пультом паузы управляют из UI.** Управление паузой выполняется отдельным DAG'ом ручного запуска (показ действующих правил, постановка, снятие, уборка истёкших), показ включает возраст и последний сработавший порог, снятие удаляет правило целиком со служебными отметками.
- **REQ-tfs-kafka-10** — **Досылка проверяет наличие файла в бакете.** Перед постановкой файла в очередь на повторную отправку система убеждается, что файл лежит в бакете, и возвращает отдельно поставленные строки и отдельно отсутствующие.
- **REQ-tfs-kafka-11** — **Сверка неподтверждённых отправок.** Система находит отправленные файлы, по которым квитанция не пришла дольше порога (по умолчанию 180 минут), и сообщает о них.
- **REQ-tfs-kafka-12** — **Отказы ТФС видны поимённо.** Заметка приёмника называет отказы (`StatusCode > 0`) поимённо (до пяти за опрос: файл, `RqUID` и код), заметка о неподтверждённых отправках содержит `RqUID`, по которому квитанция читается из бакета логов.

## Ограничения и контракты

- Состояние тракта — в S3 и таблицах, объявленных в `tfs_utils`; копии путей и имён таблиц в каталогах-потребителях запрещены (REQ-tfs-kafka-01).
- Ключ хранения квитанции — `(rq_uid, file_name)` (REQ-tfs-kafka-02).
- Сохранение одной строки с кодом `-1` и исходным текстом при невозможности разобрать сообщение как XML (REQ-tfs-kafka-02).
- Сенсор на каждый топик квитанций и запись топика-источника сообщения (REQ-tfs-kafka-03).
- Запрет чтения топиков квитанций из выгрузок: Kafka отдаёт сообщение одному потребителю в группе, чужая выгрузка съест квитанцию настоящего адресата (REQ-tfs-kafka-03).
- Скользящие лимиты маршрута по умолчанию: 10 в секунду, 200 в минуту, 500 в час и 2000 в сутки (REQ-tfs-kafka-04).
- Три области правил паузы: пакет, реплика и маршрут; выбор от частного к общему: пакет, затем реплика, затем маршрут (REQ-tfs-kafka-05).
- Срок действия правила паузы задаётся полем `until`, правило с `until` в прошлом не действует и отбрасывается при чтении (REQ-tfs-kafka-05).
- Пороги алерта о паузе растут степенями двойки от 1 часа (1, 2, 4, 8, 16 …), без верхнего предела (REQ-tfs-kafka-07).
- Отсутствие ретраев у таска-сторожа: порог отмечается в правиле до падения, повторная попытка ничего не найдёт (REQ-tfs-kafka-08).
- Порог ожидания квитанции по умолчанию 180 минут (REQ-tfs-kafka-11).
- Имя заметки приёмника квитанций — `rcv_<топик>`, формат строки — `<файл> · <RqUID> · <код>`, лимит — не больше пяти за опрос, условие отказа — `StatusCode > 0` (REQ-tfs-kafka-12).
- Заметка о неподтверждённых отправках содержит `RqUID`, по которому квитанция целиком читается из `tfs/receipts/<RqUID>.json` бакета логов (REQ-tfs-kafka-12).

## Критерии приёмки

| REQ-ID | Сценарий проверки |
|---|---|
| REQ-tfs-kafka-01 | Приёмник и ожидание смотрят в разные места: дано квитанция записана по одному пути, а ожидание ищет её по другому → действие ожидание квитанции → результат пакет висит до таймаута, и причина не видна ни в одном логе |
| REQ-tfs-kafka-02 | Квитанция на два файла с разными статусами: дано в квитанции первый файл принят, а второй отвергнут → действие разбор квитанции → результат сохраняются обе строки со своими кодами, и пакет не считается подтверждённым целиком |
| REQ-tfs-kafka-02 | Битый XML: дано сообщение не разбирается как XML → действие разбор сообщения → результат сохраняется одна строка с кодом `-1` и исходным текстом |
| REQ-tfs-kafka-03 | Квитанция чужого маршрута: дано в общем топике пришла квитанция по другому маршруту → действие приём квитанции → результат она сохраняется в общее хранилище и достаётся своему адресату по `RqUID` |
| REQ-tfs-kafka-04 | Суточный лимит выбран: дано за сутки по маршруту уже отправлено предельное число уведомлений → действие отправка уведомлений → результат остаток очереди ждёт следующего окна, а не отправляется сверх лимита |
| REQ-tfs-kafka-05 | На паузе и пакет, и маршрут: дано для строки очереди подходят оба правила → действие выбор причины → результат в причине названо правило пакета, а не маршрута |
| REQ-tfs-kafka-05 | Срок правила истёк: дано у правила указан `until` в прошлом → действие чтение правила → результат правило не действует и отбрасывается при чтении |
| REQ-tfs-kafka-06 | Очередь стоит из-за паузы: дано вся очередь придержана правилом паузы → действие проверка простоя → результат отправитель не сигналит о заторе |
| REQ-tfs-kafka-07 | Пауза висит пятый час: дано проверка застала бессрочное правило возрастом 5 часов, а последний отмеченный порог — 2 → действие проверка → результат сообщается порог 4 часа, и он отмечается в правиле |
| REQ-tfs-kafka-07 | Повторная проверка на том же пороге: дано проверка повторяется до того, как возраст достиг следующего порога → действие проверка → результат ничего не сообщается |
| REQ-tfs-kafka-07 | Правило поставлено до появления счётчика: дано у правила нет отметки о времени постановки → действие проверка → результат отсчёт начинается с момента первой встречи, а не с нуля |
| REQ-tfs-kafka-08 | Правило со сроком старше порога: дано сработал порог у правила с `until` в будущем → действие работа сторожа → результат сторож зелёный, но в логе и заметке видно возраст, порог и срок |
| REQ-tfs-kafka-09 | Повторная постановка того же правила: дано правило ставят ещё раз с теми же пользовательскими полями → действие постановка правила → результат ничего не меняется, а время постановки не обновляется |
| REQ-tfs-kafka-10 | Файла в бакете уже нет: дано досылают файл, который ТФС забрал (или который удалили по TTL) → действие досылка файла → результат он не попадает в очередь, а называется в списке отсутствующих |
| REQ-tfs-kafka-11 | Ожидание пропустили из-за паузы: дано пакет уехал позже, чем его выгрузка перестала ждать квитанцию → действие сверка неподтверждённых отправок → результат отсутствие подтверждения ловит сверка неподтверждённых, а не молчание |
| REQ-tfs-kafka-12 | ТФС отверг файл: дано пришла квитанция со `StatusCode = 101` → действие формирование заметки → результат в заметке `rcv_<топик>` строка `<файл> · <RqUID> · 101` |

# Baseline-спека: xs-export

- Дата: 2026-10-04
- Статус: реализована
- Источник: openspec/specs/xs-export/spec.md, перевод 2026-10-04

## Назначение

Выгрузки xStream: инкремент из ClickHouse уезжает в S3 по маршруту ТФС, а приёмная сторона узнаёт о файле сообщением в Kafka. DAG на каждую выгрузку генерируется из файла метаданных, а поведение конкретной поставки задаётся строкой реестра в ClickHouse — код при добавлении таблицы или смене формата не правится. Тракт этот старше ЕР и живёт по своим правилам: состояние ведётся в общей с ЕР таблице истории, а догон отставшей дельты сделан самоперезапуском DAG'а.

## Требования

- **REQ-xs-export-01** — **DAG'и генерируются из файла метаданных.** Система создаёт по DAG'у на каждую запись файла метаданных выгрузок. Отсутствие файла не роняет разбор модуля: система записывает ошибку в лог и не создаёт ни одного DAG'а.
- **REQ-xs-export-02** — **Запросы собираются из общих колонок и специфичных частей.** Метаданные хранят список колонок, общий для трёх запросов поставки (обновление витрины, загрузка инкремента, выгрузка инкремента), а различия — отдельными полями: дополнительные колонки, источник, соединения, условие, хвост. Запрос, который не разложился на части, хранится и подставляется целиком.
- **REQ-xs-export-03** — **Поведение поставки задаётся реестром в ClickHouse.** Каждая поставка читает свои настройки из реестра выгрузок: признак активности, нужна ли оптимизация витрины, нужно ли автоподтверждение прошлого инкремента, нижняя граница окна, таймаут самоперезапуска, тип и расширение сжатия, максимальный размер файла, правила очистки текста и формат CSV. Незаполненные значения наследуются от строки по умолчанию.
- **REQ-xs-export-04** — **Число строк ограничивается на неболевых контурах.** Запрос выгрузки инкремента оборачивается ограничением числа строк по значению `ENV_STAND`: на боевом контуре ограничения нет, на прочих известных действует лимит из карты. Неизвестный контур работает без ограничения.
- **REQ-xs-export-05** — **Состояние инкремента ведётся историей выгрузок.** Каждая стадия отмечается отдельной записью в общей таблице истории: границы окна и число строк после загрузки, время отправки после передачи файлов, время подтверждения при автоподтверждении. Прежние записи не переписываются — состояние наращивается.
- **REQ-xs-export-06** — **Маршрут ТФС зависит от контура и потока данных.** Идентификатор сценария, префикс в бакете и пул отправки выбираются по потоку данных поставки, причём карта маршрутов на боевом контуре и на прочих разная: в бою все потоки идут одним маршрутом, на остальных контурах — каждый своим.
- **REQ-xs-export-07** — **Имя файла выводится из метаданных поставки.** Имя выгружаемого объекта строится из имени файла поставки и метки времени запуска, а не из времени разбора DAG-файла. Метка берётся из логической даты запуска, чтобы переживать повторы задачи и не меняться между разборами.
- **REQ-xs-export-08** — **Фабрика передаёт группе задач всё, что той нужно.** Фабрика DAG'ов передаёт в сборщик группы задач полный набор метаданных поставки, включая имя файла: по нему выбирается маршрут ТФС и строится имя объекта в S3. Набор параметров фабрики и ожидания сборщика не расходятся.
- **REQ-xs-export-09** — **Число строк попадает в имя объекта.** После выгрузки система переименовывает объект, добавляя в имя число частей и число строк, и удаляет исходный объект. Переименование выполняется копией, а сообщение в Kafka уходит уже с конечным именем.
- **REQ-xs-export-10** — **Уведомление ТФС отправляется по формату и с выдержкой темпа.** Сообщение о выгруженном файле собирается в формате `TransferFileCephRq` с уникальным идентификатором запроса и временем, отправляется в топик маршрута из пула этого маршрута и выдерживает паузу перед отправкой. Недоставленное сообщение не считается отправленным: ошибка доставки роняет задачу, чтобы сработал повтор.
- **REQ-xs-export-11** — **Отставшая дельта догоняется самоперезапуском.** Если после отправки окно дельты не дошло до текущего момента, система планирует следующий запуск того же DAG'а через таймаут из реестра. Достигнутый конец цикла завершает DAG без нового запуска.

## Ограничения и контракты

- Расписание по умолчанию — ежедневное (REQ-xs-export-01).
- DAG выключен при создании (REQ-xs-export-01).
- Общие теги каталога (REQ-xs-export-01).
- Наследование настроек от строки по умолчанию в реестре (REQ-xs-export-03).
- Лимит строк по `ENV_STAND` (бой без лимита, неизвестный контур без лимита) (REQ-xs-export-04).
- Разные карты маршрутов ТФС для боя и прочих контуров (REQ-xs-export-06).
- Имя объекта с числом частей и строк (REQ-xs-export-09).
- Формат `TransferFileCephRq` (уникальный идентификатор запроса и время) (REQ-xs-export-10).
- Пауза перед отправкой (REQ-xs-export-10).

## Non-goals

В исходной спецификации границы не записаны; дополняется при первой дельте

## Критерии приёмки

| REQ-ID | Сценарий проверки |
|---|---|
| REQ-xs-export-01 | Новая выгрузка: дано в файл метаданных добавлена запись → действие разбор файла → результат после разбора файла в Airflow появляется соответствующий DAG, кода никто не правил |
| REQ-xs-export-01 | Файл метаданных не выложен: дано файла метаданных нет → действие разбор модуля → результат в логе ошибка с путём, а разбор завершается без исключения |
| REQ-xs-export-01 | Расписание не указано: дано у записи нет расписания → действие планирование расписания → результат DAG получает ежедневное расписание по умолчанию |
| REQ-xs-export-01 | Выгрузка появилась впервые: дано DAG создан из новой записи → действие разбор файла → результат он выключен при создании и помечен общими тегами каталога, по которым выгрузки xStream отличимы от прочих DAG'ов контура |
| REQ-xs-export-02 | Запрос со своим условием: дано у выгрузки инкремента есть собственные `JOIN` и `WHERE` → действие сборка запроса → результат запрос собирается из общего списка колонок плюс собственных, с этими соединениями и условием |
| REQ-xs-export-02 | Запрос, который не разбирается: дано SQL не удалось разложить на части → действие сборка запроса → результат он хранится как есть и подставляется без изменений |
| REQ-xs-export-03 | Выгрузка выключена: дано в реестре у поставки снят признак активности → действие запуск поставки → результат запуск обрывается сразу после проверки, ни один запрос к данным не выполняется |
| REQ-xs-export-03 | Смена формата выгрузки: дано нужно поменять сжатие, разделитель или правила очистки текста → действие обновление настроек → результат достаточно правки строки реестра — выкладка кода не требуется |
| REQ-xs-export-03 | Значение не задано у поставки: дано у поставки не заполнен параметр, заполненный в строке по умолчанию → действие чтение настроек → результат используется значение строки по умолчанию |
| REQ-xs-export-04 | Прогон на тестовом контуре: дано `ENV_STAND` соответствует тестовому контуру → действие запуск выгрузки → результат в S3 уезжает не больше предусмотренного числа строк, независимо от размера дельты |
| REQ-xs-export-05 | Подтверждение предыдущего инкремента: дано у поставки включено автоподтверждение, а предыдущий инкремент отправлен, но не подтверждён → действие запуск выгрузки → результат для него добавляется запись с временем подтверждения, и следующее окно отсчитывается от него |
| REQ-xs-export-05 | Автоподтверждение выключено: дано признак автоподтверждения снят → действие запуск выгрузки → результат ветка подтверждения пропускается, а подтверждение приходит извне |
| REQ-xs-export-06 | Поставка потока, которого нет в карте: дано имя файла указывает на поток, отсутствующий в карте маршрутов → действие сборка DAG'а → результат DAG не собирается, и это видно при разборе файла, а не при выгрузке в бой |
| REQ-xs-export-07 | Повтор упавшей задачи: дано задача выгрузки перезапускается после падения → действие перезапуск задачи → результат объект пишется под тем же именем, а не под новым |
| REQ-xs-export-07 | Файл разобран заново между запусками: дано — → действие обработчик перечитал файл DAG'а → результат имена объектов прежние: два запуска не сходятся в один ключ и не затирают друг друга |
| REQ-xs-export-08 | Сборщику не хватило метаданных: дано фабрика передала набор без имени файла → действие сборка группы задач → результат ни один DAG выгрузок не создаётся — сборка падает на первой же поставке, и вместо выгрузок в UI видна ошибка разбора файла |
| REQ-xs-export-09 | Выгрузка разбита на части: дано данные не поместились в один файл и выгружены несколькими → действие переименование объектов → результат каждая часть получает своё имя с числом частей и числом строк, и по каждой уходит своё сообщение |
| REQ-xs-export-10 | Kafka отвергла сообщение: дано брокер вернул ошибку доставки → действие обработка ответа брокера → результат задача падает и повторяется, а не завершается успешно с записью в логе |
| REQ-xs-export-11 | Поставка отстала на несколько окон: дано после отправки признак конца цикла не выставлен → действие обработка завершения → результат тот же DAG запускается снова на рассчитанное время и продолжает догон |
| REQ-xs-export-11 | Дельта догнала настоящее: дано признак конца цикла выставлен → действие планирование запуска → результат ветка планирования пропускается, запуск завершается, и следующий будет по расписанию |

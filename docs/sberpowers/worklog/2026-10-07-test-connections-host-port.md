## Отклонения от плана

- Три fix-прохода вместо ноля: план описывал только корректные значения extra. Ревью нашло, что
  кривое значение роняет сбор (`ValueError` из `urlsplit`, extra не объект), что подпись может
  превысить колонку метабазы (250), а потом — что текст исключения выносит в лог кусок значения.
  Причина: в плане и спеке не было раздела «непригодные входные данные».
- Спека дополнялась по ходу исполнения (предел подписи, правило непригодного адреса, `null`,
  порт у каждого хоста) — дважды по решению человека на ревью, один раз — моим решением по
  находке (предел 250) с подтверждением на итоговом ревью.
- Задача начиналась мимо процесса: правка кода сразу, без спеки; откачена, пройден полный цикл.

## Уроки на следующий цикл

- В спеке, где значение приходит из подключения или extra, сразу писать требование на
  непригодный вход (тип, разбор, диапазон, пустые части) и что делать — падать или пусто с
  предупреждением: в этом цикле его отсутствие стоило двух fix-проходов и двух правок спеки.
- Причину в предупреждении писать постоянным текстом, а не текстом исключения: сообщения stdlib
  (`urllib`, `int()`) содержат фрагмент разбираемого значения.
- Подпись `map_index_template` с данными из внешнего источника — сразу ограничивать 250
  символами: Airflow 2.11 колонку не обрезает.
- Проверку правила для дага без Airflow делать через вынимание функций из модуля `ast`-ом
  (`testbed/check_conn_addr.py`): запускается локально за доли секунды, импорт дага не нужен.
- Подставляя дату в строку через `%`, не применять подстановку к коду с `%s` — в черновике до
  процесса так испортился формат лога (ошибка `Logging error` на стенде).

ADR не нужен: решение легко обратимо (правило адреса — одна функция, вывод — без смены
контрактов, кроме добавленного ключа XCom).

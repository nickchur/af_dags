# ctl-worker

## ADDED Requirements

### Requirement: Пул задачи — по внешнему ресурсу, размеры пулов меняет только сторож подключений

Задача агента SHALL занимать пул того внешнего ресурса, который она тратит: вызовы API CTL —
`ctl_pool`, нагрузка на Greenplum — `gp_pool`, переносы ТФС — `files_pool`. Задачи, не
тратящие ни одного из них, — заметки, публикация Dataset'ов, — SHALL сидеть в `default_pool`.
Размер пулов подключений SHALL менять только сторож подключений (`CTL.<profile>.test_conn`),
и сам он SHALL сидеть в пуле, который никто не обнуляет. Сбой проверки MUST NOT останавливать
сторожа: пул закрыт, а проверка продолжается, чтобы вернуть размер, когда подключение оживёт. `ctl_pool` SHALL иметь фиксированный
размер, а не расти вслед за очередью. Сенсор MUST NOT останавливать приём загрузок из-за
недоступности подключения, которое ему не нужно.

#### Scenario: CTL недоступен

- **WHEN** CTL перестал отвечать
- **THEN** `ctl_pool` обнуляет только сторож; предварительные проверки в задачах падают, не
  трогая пул; когда CTL ожил, сторож возвращает пулу размер на следующей проверке, а не
  в следующем ране

#### Scenario: Сторож не запирает себя

- **WHEN** сторож обнулил пул недоступного подключения
- **THEN** его следующая проверка запускается, потому что сам он в этот пул не входит

#### Scenario: Недоступен S3-архив

- **WHEN** не отвечает подключение, нужное только переносам ТФС
- **THEN** закрывается `files_pool`, а сенсор продолжает принимать загрузки

# Пулы CTL — по ресурсу, размеры меняет только сторож подключений

## Why

Размер пулов `ctl_worker` меняли десять мест. `chk_any_conn` зовётся как предварительная
проверка в `run_prm`, `run_exe`, `run_end`, `ctl_loader`, `ctl_monitor`, `ctl_events`,
`ctl_test` и в группе `chk_conn` сенсора. Каждый удачный вызов писал размер пула в
`slot_pool`, неудачный — обнулял. Три проверки CTL сидели в самом `ctl_pool`: при сбое CTL
они запирали пул и сами больше в него не попадали. Выручал только `test_conn` из `pg_pool`.

Группа `chk_conn` в сенсоре (помечена «не вызывается!», хотя работала) ставила шесть задач в
`pg_pool` на каждый прогон, то есть каждую минуту. Падение любой из них, хоть S3-архива,
останавливало приём загрузок. В ту же очередь `pg_pool` упирался `test_conn` (21 failed подряд
на альфе, 12–14.09.2026).

Динамический `ctl_pool` (10–40) шёл за очередью, а не ограничивал её: в пик CTL получал больше
одновременных вызовов именно тогда, когда ему тяжелее. `rate_limit` в `ctl_api` считает внутри
процесса, а у каждой задачи свой процесс — между задачами он ничего не ограничивает, хотя
спека обещала «на пул».

Журнал GET-запросов CTL в GP (`pr_log_ctl`) писался только при закрытом `gp_pool`, то есть
когда GP недоступен. Это ошибка с первого коммита.

## What Changes

- **Размер пулов меняет только `CTL.<profile>.test_conn`:** `chk_any_conn(manage_pool=True)`,
  сам он в `default_pool`. Предварительные проверки только проверяют. Чтение размера — новая
  `pool_size()`, которая не пишет и не создаёт пул.
- **`ctl_pool` фиксированный, 20.** Устаревший диапазон в Variable даёт 20 с предупреждением.
- **Пул задачи — по ресурсу:** CTL API → `ctl_pool`, Greenplum → `gp_pool`, заметки и
  Dataset'ы → `default_pool`. `pg_pool` больше не используется; у `pg`, `ppl`, `s3`, `tfs` пулов
  нет, проверки остаются.
- **Группа `chk_conn` в сенсоре убрана** — её делает `test_conn`, а защиту дают пулы.
- **Журнал в GP** пишется, когда `gp_pool` открыт; значения передаются параметрами.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `plugins`: «Единая проверка доступности подключений», «Обращения к CTL API ограничены по
  темпу и повторяются при обрыве».
- `ctl-worker`: новое требование «Пул задачи — по внешнему ресурсу, размеры пулов меняет
  только сторож подключений».

## Impact

- **Код:**
  - `plugins/utils.py`: `pool_slots`, `pool_size`, `get_current_load`;
  - `plugins/ctl_core.py`: `chk_any_conn`;
  - `plugins/ctl_utils.py`: `ctl_api`, `rate_limit`;
  - `ctl_worker/`: `ctl_test_conn`, `ctl_sensor`, `ctl_events`, `ctl_test`, `ctl_config`;
  - `ctl_config.json`.
- **Метабаза:** в `slot_pool` пишет один сторож — было десять мест, из них шесть задач сенсора
  в минуту. Группа `chk_conn` снимает ~8,6 тыс. задач в сутки на альфе.
- **Greenplum:** на каждый GET к CTL (кроме `statval` и `tmpl`) — вызов `pr_log_ctl`, если GP
  доступен. При нестабильном GP `gp_exe` повторяет его до трёх раз, и вызов CTL ждёт.
- **Выкладка:** перезапустить `ctl_config`; пулы `pg_pool`, `ppl_pool`, `s3_pool`, `tfs_pool`
  можно удалить руками.

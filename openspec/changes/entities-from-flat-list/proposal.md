# Список сущностей строится из плоского списка CTL, а переменная не отстаёт от S3

## Why

Экспорт `CTL_HR_Data.yml` на альфе больше суток выгружал 680 сущностей вместо 682. Не
хватало ровно двух самых новых детей узла `NONHR_STG` — `941010665 ub.prod_map` и
`941010666 ub.market_monitor` (последние id из 152), на которые ссылаются воркфлоу
`dia2stg_prod_map` и `dia2stg_market_monitor` из того же архива.

Источником был поиск по дереву:
`/v4/api/entity/tree?search=<корень>&offset=0&limit=<ctl_limit>`. Уровни 0 и 1 приходили
целыми, обрезка по `limit` исключена (682 < 1000) — не хватало именно свежесозданных.
Так ведёт себя отстающий поисковый индекс: `/v4/api/entity` читает таблицу и отдаёт обе
сущности. Тот же плоский список даг уже выгружает каждый круг для `ctl_entities_all`.

Отдельно — ловушка в `ctl_obj_save`: при совпадении MD5 функция выходила раньше записи
Variable. Это было записано и в спеке («ни объект, ни Variable не переписываются»), то есть
решение сознательное — экономия одной записи за круг. Разворачиваем его: Стоило переменной один раз отстать от S3 — она не догоняла никогда, а
читатели берут сначала переменную. Сегодня это не причина, но следующий сбой записи
заморозил бы любой объект, включая `ctl_workflows`, по которому строится фабрика дагов.

## What Changes

- `ctl_entities` собирается из `/v4/api/entity` обходом вниз по `parentId` от
  `root_entity`; запрос `entity/tree` убран вместе с использованием `ctl_limit` (он про
  загрузки и равен 1000, а написанный рядом fallback `10000` не применялся никогда).
- Порядок обхода фиксирован (в ширину, дети по возрастанию id): на нём стоит сравнение MD5,
  и зависеть от порядка ответа CTL он не должен.
- Сверка вместо молчания: в заметку пишется размер поддерева и сколько сущностей «нашего»
  семейства id оказались вне его (штатно — то, что выше корня).
- Полный список выгружает `load_entities`, а `load_events` читает готовый из S3 —
  второй выгрузки на 80 МБ за круг не появляется.
- `ctl_obj_save` обновляет Variable и тогда, когда объект в S3 не изменился.

## Capabilities

### Modified Capabilities

- `ctl-worker`: новое требование «Список сущностей полон и берётся из плоского списка».
- `plugins`: уточнение требования «Объекты читаются из Variable, а хранятся в S3».

## Impact

- Код: `ctl_worker/ctl_loader.py` (`load_entities`, `load_events`),
  `plugins/ctl_utils.py` (`ctl_obj_save`, новая `_var_set`).
- Контракт с CTL: вместо `/v4/api/entity/tree` используется `/v4/api/entity`.
- Данные: на первом прогоне после выкладки `ctl_entities.json` перезапишется один раз —
  порядок обхода другой.

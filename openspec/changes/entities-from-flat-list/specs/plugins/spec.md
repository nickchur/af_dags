# plugins

## MODIFIED Requirements

### Requirement: Объекты читаются из Variable, а хранятся в S3

`ctl_obj_load` SHALL сначала искать объект в Airflow Variable и обращаться к S3 только при
её отсутствии; `ctl_obj_save` SHALL писать объект в S3 и обновлять Variable по требованию.
Для проверки изменений SHALL существовать способ узнать хэш объекта в S3 без загрузки тела
(`ctl_obj_etag`).

Variable SHALL обновляться независимо от того, изменился ли объект в S3. Совпадение хэшей
означает только то, что загружать тело не нужно, — переменная при этом может отставать, а
догнать сама она не сможет: читатели берут её первой.

#### Scenario: Объекта нет нигде

- **WHEN** ни Variable, ни ключ в S3 не существуют
- **THEN** возвращается пустой словарь, а не исключение

#### Scenario: Проверка изменений большого объекта

- **WHEN** нужно узнать, изменился ли объект в S3
- **THEN** достаточно запроса заголовков (`ETag`), тело объекта не скачивается

#### Scenario: Сохранение неизменившегося объекта

- **WHEN** хэш нового содержимого совпал с `ETag` уже лежащего в S3 объекта
- **THEN** объект не переписывается и вызывающему возвращается признак «записи не было»,
  а Variable всё равно приводится к сохраняемому набору — иначе отставшая переменная
  остаётся отставшей навсегда

## Происхождение

- **Запись Variable вынесена из-под проверки хэша.** До 17.09.2026 совпадение MD5 выходило
  из `ctl_obj_save` раньше блока записи переменной: отстав один раз — из-за сорванной записи
  в метабазу, ручной правки или восстановления из старого экспорта, — переменная не
  догоняла никогда, потому что объект в S3 оставался тем же. Проверено на стенде: подменённая
  переменная после сохранения того же набора оставалась подменённой. Пересматривать, если
  читатели перестанут предпочитать Variable объекту в S3.

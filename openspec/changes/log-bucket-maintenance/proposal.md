# Обслуживание бакета логов: сроки по папкам, один обход, статистика

## Why

`tools_log_cleanup` обслуживал только префикс логов задач: бакет был общий, и трогать чужое
было нельзя. Теперь бакет наш целиком, а в нём, кроме логов задач, лежат снимки дагов
(`dag_snapshots/`), дампы очереди (`queue_cleanup/`), снимки активности метабазы
(`pg_activity/`), проба здоровья (`_system_health/`) и — с появлением отбивок воркеров в
etl-core — `_health/`, куда каждый под пишет строку раз в минуту: 24 объекта в сутки на
процесс. Сроков хранения у этих папок нет, и завести их некому: платформенное ядро бакет не
настраивает (правá на lifecycle у воркера нет, да и делать это на каждом старте пода
неправильно).

Второе: непонятно, работают ли правила жизненного цикла. В `check/pg_activity.py` записано,
что через корпоративный шлюз `PutBucketLifecycleConfiguration` отвечал «Missing required
header», поэтому там чистят руками. Обход в `s3_utils.s3_set_ttl` с тех пор появился, но
проверить это можно только по факту: остались ли объекты старше срока.

## What Changes

- Сроки хранения задаются по папкам: логи задач — параметром `days`, остальные — картой
  `folders` (префикс → дни), незнакомые папки — `other_days`, по умолчанию `0` (не трогать).
  Всё это, как и раньше, живёт в переменной `tools_log_cleanup_params`.
- Таск `layout` создаёт бакет и выставляет правило жизненного цикла на каждый префикс.
  Отказ правила не роняет прогон: уборку делает обход, а отчёт показывает, сработали ли
  правила.
- Уборка и статистика — один обход бакета вместо двух листингов: по каждой папке объекты,
  объём, самый старый и свежий, разбивка по типам файлов и сколько удалено.
- Отчёт: таблица по папкам в заметку таска и DAG-а, сводка — в XCom.
- Соседние даги свои дампы убирают сами: их сроки здесь стоят не меньше их `keep_days`, этот
  DAG для них страховка.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `check`: требование «Чистится ровно бакет логов задач» превращается в «Бакет логов
  обслуживается по папкам».

## Impact

- Код: `check/log_cleanup.py` (v1.7), `check/readme.md`.
- Внешняя система: S3, бакет логов. Добавляются правила жизненного цикла на префиксы и
  удаление в папках, которым задан срок. Незнакомые папки по умолчанию не трогаются.
- Связано с etl-core: префикс `_health/` появляется вместе с отбивками воркеров; без срока
  хранения он растёт.

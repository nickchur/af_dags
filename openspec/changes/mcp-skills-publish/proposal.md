# Навыки агента из репозитория дагов — на MCP-эндпоинт через Variables

## Why

Навык `ctl-worker` лежит в этом репозитории (`ctl_worker/skill/ctl-worker.md`), а
MCP-эндпоинт вебсервера отдаёт только навык из пакета etl-core (`airflow://skill`). Агент
на af-alpha-dev искал `airflow://skill-ctl-worker` и `airflow://ctl-worker` — оба
«Resource not found»; ставить навык клиенту руками приходилось каждому.

Прямо из дагов вебсервер навык взять не может: синхронизация из S3 кладёт файлы только
шедулеру, dag-processor'у и воркеру, каталог дагов вебсервера пуст (сигма и альфа), а
читать S3 напрямую вебсерверу сигмы запрещено.

## What Changes

- Новый даг `tools_mcp_skills` (`tools/mcp_skills.py`, раз в 30 минут): находит
  `*/skill/*.md` в каталоге дагов воркера (кроме `testbed/` и скрытых) и кладёт текст в
  Variable `mcp_skill__<имя>`, оглавление — в `mcp_skills` (имя → sha256, путь, размер).
  Пишет только изменившееся, снимает навык, чей файл исчез; дубль имени и файл больше
  256 КБ — ошибка таска.
- Эндпоинт (etl-core, HRPDATALAB-15414) отдаёт их ресурсами `airflow://skills` и
  `airflow://skill/<имя>`, читая метабазу.

## Impact

- Контракт с etl-core: ключи `mcp_skill__<имя>` и `mcp_skills` меняются только вместе с
  `sber_app_dataplatform_etl_core/mcp_skill.py`.
- Навык на эндпоинте отстаёт от выложенных дагов не больше чем на 30 минут.

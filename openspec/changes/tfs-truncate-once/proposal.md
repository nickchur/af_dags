# Усечение таблицы при приёме файлов ТФС — одно на прогон, а не на файл

## Why

`run_tfs` берёт файлы маской (`keys = s3_keys(path)`) и грузит каждый своим вызовом
`gp_upload_s3_csv(..., truncate=truncate)`. Флаг передаётся на каждый файл, а усечение идёт
своей транзакцией — значит при заданном `wf_tfs_table` каждый следующий файл стирает
таблицу, которую наполнил предыдущий, и в ней остаётся только последний.

Многофайловость тут не гипотетическая: в бакете тракта ТФС на стенде (копия боевого потока)
2994 объекта, из них 2446 архивов, и все они трёхчленные (`.tkt` + `.meta` + `.csv`), а части
приходят отдельными объектами — `…__1_1_0`, `…__1_1_50`.

Тем же заходом закрыт близнец внутри архива (`plugins`, PR #63): там усечение уходило на
каждый файл ZIP. Теперь счёт ведётся и по объектам, и внутри объекта.

## What Changes

- `run_tfs` усекает таблицу один раз за прогон: ведётся множество уже усечённых таблиц.
- Когда таблица берётся из имени файла (`wf_tfs_table` пуст), усечение на файл остаётся
  верным: таблицы разные, поэтому счёт именно по таблицам, а не по числу файлов.
- Файл, упавший до усечения, права очистить не тратит — оно переходит следующему.

## Capabilities

### Modified Capabilities

- `ctl-worker`: новое требование «Усечение при приёме файлов — одно на таблицу за прогон».

## Impact

- Код: `ctl_worker/ctl_worker.py`, таск `run_tfs`.
- Поведение: воркфлоу с `wf_tfs_table` и `wf_tfs_truncate` перестаёт терять все файлы, кроме
  последнего. Воркфлоу без явной таблицы работает как раньше.

### [s3_to_zip.py](s3_to_zip.py)

Ежедневная выгрузка-копия: раз в сутки (по умолчанию 01:30 MSK) объекты S3 за вчера по MSK — по архиву
ZIP64 на каждый путь из `src`. Исходники не трогает. Сборка потоковая: объекты читаются по одному и уходят
в multipart-загрузку частями по 64 МБ — без диска воркера и без буфера под весь архив. Сбой посреди записи
отменяет загрузку, частичного архива в приёмнике не остаётся.

**Таски:** `params` (сохранение параметров) → `jobs` (раскладка по архивам) → `archive` (экземпляр на src,
по одному за раз; в UI подписан именем архива).

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `src` | `[префикс логов задач из [logging]]` | список `conn_id://бакет/путь`, на каждый — свой архив. Без маски — всё под путём, с `*` `?` — по ключу (fnmatch: `*` проходит и через `/`, `logs/*.log` возьмёт `logs/a/b.log`) |
| `dst` | `archive/` бакета логов | папка с `/` — имя `<последняя папка src>[_<метка>].zip`, совпавшие имена получают номер (`airflow-logs_2`); ключ `….zip` — только при одном src |
| `date_from` / `date_to` | пусто = вчера по MSK | `LastModified` в MSK, обе границы включительно; задана одна — вторая без границы. Разовые: не сохраняются |
| `add_ts` | true | метка `_YYYYMMDD_HHMMSS` (UTC, старт рана, одна на ран) к имени, и перед `.zip` ключа тоже; без неё повтор с тем же именем упрётся в `replace` |
| `max_size_gb` | 20 | на каждый архив: сырой объём больше — экземпляр красный до начала записи; 0 — без лимита |
| `replace` | false | архив с таким ключом уже есть — экземпляр красный |
| `schedule` | `30 1 * * *` | cron в MSK или пресет; пусто — только вручную; применяется со следующего парсинга |
| `save_params` | false | сохранить параметры запуска как значения по умолчанию (переменная `tools_s3_to_zip_params`) |

- Пути внутри архива — от префикса `src` (часть до маски), время записи — `LastModified`.
- `.gz` `.zip` `.parquet` не пережимаются (deflate уровня 0), остальное — deflate.
- Пустой отбор у src — экземпляр skipped («нечего архивировать»), ран зелёный: пустой день — норма.
- Превышение лимита, существующий архив, `dst` на `.zip` при нескольких src — красный без ретраев.
- Пропущенные сутки ран сам не догоняет (catchup выключен) — вручную диапазоном дат.
- Итог — заметка экземпляра `archive`: путь, число файлов, сырой объём и объём архива, скорость.
- Если под убит жёстко (OOM, SIGKILL), отмена загрузки не успевает, и части остаются в квоте невидимыми.
  Их снимает следующий запуск с тем же именем архива: незавершённые загрузки `<имя>.zip` и
  `<имя>_<YYYYMMDD_HHMMSS>.zip` в папке `dst` отменяются (список — в заметке, `aborted`); чужие имена
  не трогаются.

⚠️ Архив в бакете логов живёт по общему правилу хранения бакета (120 дней прод, 30 дев).
Для долгого хранения указывайте `dst` в другом бакете.

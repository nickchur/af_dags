### [s3_to_zip.py](s3_to_zip.py)

Выгрузка-копия: объекты S3 по пути, маске и датам — в один ZIP64 в S3. Исходники не трогает.
Сборка потоковая: объекты читаются по одному и уходят в multipart-загрузку частями по 64 МБ —
без диска воркера и без буфера под весь архив. Сбой посреди записи отменяет загрузку, частичного
архива в приёмнике не остаётся.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `src` | префикс логов задач из `[logging]` | `conn_id://бакет/путь`: без маски — всё под путём, с `*` `?` — по ключу (fnmatch) |
| `dst` | `archive/` бакета логов | ключ `….zip` как есть; папка с `/` — имя `<последняя папка src>_<YYYYMMDD_HHMMSS UTC>.zip` |
| `date_from` / `date_to` | пусто | `LastModified` в UTC, обе границы включительно |
| `max_size_gb` | 20 | сырой объём больше — ран красный до начала записи; 0 — без лимита |
| `replace` | false | архив с таким ключом уже есть — ран красный |

- Пути внутри архива — от префикса `src` (часть до маски), время записи — `LastModified`.
- `.gz` `.zip` `.parquet` не пережимаются (deflate уровня 0), остальное — deflate.
- Пустой отбор, превышение лимита, существующий архив — красный ран без ретраев.
- Итог — заметка таска `archive`: путь, число файлов, сырой объём и объём архива, скорость.
- Если под убит жёстко (OOM, SIGKILL), отмена загрузки не успевает, и части остаются в квоте невидимыми.
  Их снимает следующий запуск: незавершённые загрузки `*.zip` прямо в папке `dst` отменяются (список — в
  заметке, `aborted`). Поэтому в папку `dst` не должен писать никто, кроме этого дага.

⚠️ Архив в бакете логов живёт по общему правилу хранения бакета (120 дней прод, 30 дев).
Для долгого хранения указывайте `dst` в другом бакете.
